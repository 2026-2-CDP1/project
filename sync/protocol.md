## 1. 기록 조건표

아래 값은 **모든 에피소드에서 바꾸지 않습니다.** 바꿔야 하면 이유를 적고 팀에 알립니다.

| 항목 | ego (머리, 헤드 마운트) | exo (삼각대) |
|---|---|---|
| 카메라 모델 | iPhone 16 | iPhone 18 Pro |
| 촬영 앱 | Spectacular Rec | Spectacular Rec |
| 렌즈 | 1x 메인(광각) 렌즈 고정 | 1x 메인(광각) 렌즈 고정 |
| 해상도 | 1920×1440 (앱 기본, 4:3) | 1920×1440 (앱 기본, 4:3) |
| 프레임 속도 | 30 fps | 30 fps |
| 노출·셔터 | 녹화 중 고정, 목표 셔터 1/500 s 이상 (설정 가능 여부 확인 필요) | 같음 |
| 초점·화이트밸런스 | 잠금 (초점 고정 가능 여부 확인 필요) | 같음 |
| 손떨림 보정·HDR | 끔 | **반드시 끔** |
| 프레임별 시각(타임스탬프) 출처 | `data.jsonl`의 프레임 `time` (기기 시계, s) | 같음 |
| 소리 녹음 | 불가 (앱이 오디오를 저장하지 않음) | 같음 |
| 저장 형식 | `.mov`, H.264 | 같음 |

### 앱이 저장하는 파일 (exo, iPhone 18 Pro에서 확인)

녹화 1회 = 폴더 1개 (`recording_YYYY-MM-DD_HH-MM-SS/`)

| 파일 | 내용 |
|---|---|
| `data.mov` | 영상 (H.264, 1920×1440, 30 fps 고정, 오디오 없음) |
| `data.jsonl` | 한 줄에 하나씩: 프레임 기록(`number`, `time`, 노출 시간 `exposureTimeSeconds`, 프레임별 내부 파라미터 `calibration`)과 IMU(가속도·자이로·자기) |
| `calibration.json` | 녹화 시작 시점 내부 파라미터 (pinhole: fx, fy, cx, cy — 왜곡 계수 없음) |
| `frames2/` | 프레임별 LiDAR 깊이 PNG (256×192, 16 bit, 단위 mm) — LiDAR가 있는 기종만 |
| `metadata.json` | 기기 모델 (`iPhone19,2`), 플랫폼 |

- 프레임 시각은 각 기기의 시계 기준이라 두 폰의 시각을 바로 비교할 수 없습니다. 두 영상의 시간 차는 박수로 구합니다(4절).
- LiDAR 깊이는 3번 담당이 exo 손목 3D 위치를 뽑을 때 참고할 수 있습니다.

### 값을 이렇게 정한 이유

- **exo = iPhone 18 Pro.** exo 영상은 보정 후 손목 3D 위치 추출과 OpenVLA 입력 이미지로 쓰여 화질이 더 중요하고, LiDAR 깊이도 나옵니다. ego는 엄지–검지 거리만 쓰고 머리에 올리므로 가벼운 기기가 낫습니다.
- **30 fps.** 두 카메라를 같게 맞춥니다. 저크(5-2 지표)는 3차 차분 ÷ Δt³이라 fps가 높을수록 키포인트 노이즈가 커집니다(60 fps면 30 fps의 약 8배). 번짐은 fps 대신 빠른 셔터로 잡습니다.
- **빠른 셔터, 노출 고정.** 빠른 동작 케이스에서 손이 번지면 키포인트가 흔들립니다. 셔터를 빠르게 하면 화면이 어두워지므로 조명을 밝게 합니다.
- **렌즈·초점 고정.** 렌즈나 초점이 바뀌면 내부 파라미터가 달라져 exo 보정값이 무효가 됩니다. 시험 녹화에서 녹화끼리 초점거리(fx)가 1386 px vs 1404 px로 1.3% 달랐습니다.
- **손떨림 보정 끔.** 보정은 화면을 잘라내고 프레임마다 기하를 바꿔 exo 보정을 깨뜨립니다.
- **싱크는 박수 영상 프레임으로.** 앱이 소리를 저장하지 않으므로 두 영상에서 손바닥이 처음 닿는 프레임을 눈으로 찾습니다. 오차는 ±1프레임(30 fps에서 약 33 ms)입니다.
- **H.264.** HEVC(H.265)는 서버 OpenCV에서 디코딩이 안 될 수 있습니다.
- **기종이 다름.** 녹화 시작 지연과 시계 속도가 기기마다 달라 드리프트가 생길 수 있습니다. 끝 박수를 반드시 넣습니다(4절).

### 시험 촬영으로 확인할 것

확인됨 (2026-10-05 exo 시험 녹화 2개, iPhone 18 Pro):

- [x] 저장 형식 — `.mov`, H.264, 1920×1440, 30 fps 고정
- [x] 프레임별 시각 — `data.jsonl`에 프레임마다 기록됨
- [x] 프레임 간격이 일정한가 — 모든 프레임 0.0333 s, 흩어짐 약 1e-7 s (`ffprobe` 결과와도 일치)
  ```bash
  ffprobe -v error -select_streams v:0 -show_entries frame=best_effort_timestamp_time \
    -of csv=p=0 data.mov > data_ts.csv
  ```
- [x] 소리 — 오디오 트랙 없음 → 박수 영상 프레임으로 싱크
- [x] 노출 — 녹화 하나 안에서는 고정, 그러나 녹화마다 다름 (1/120 s, 1/60 s)

남은 것:

- [ ] Spectacular Rec에서 셔터 속도·ISO를 직접 고정할 수 있는가 (안 되면 다른 앱 검토)
- [ ] 초점을 고정할 수 있는가 — 고정 후 녹화 2개 이상에서 fx가 같게 나오는지 `data.jsonl`로 확인
- [ ] 앱이 주는 내부 파라미터에 왜곡이 무시할 만한가 — 체커보드 몇 장으로 확인 (3절)
- [ ] ego(iPhone 16)도 같은 형식으로 저장되는가 — 시험 녹화 1회로 파일 구성·해상도·fps·프레임 시각 확인
- [ ] 1/500 s 셔터에서 실내 조명으로 밝기가 충분한가
- [ ] 헤드 마운트에서 ego 화면에 손이 잘 들어오는가
- [ ] 박수 순간이 두 영상에서 모두 선명하게 보이는가 (손바닥이 닿는 프레임을 찾을 수 있는지)
