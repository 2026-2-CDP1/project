# 촬영 프로토콜

> 대상: 3번 수집·가공 담당 — 이 문서만 보고 촬영할 수 있게 썼습니다.
> 작성·문의: 신서연 (2. 촬영 프로토콜·싱크)
> 상태: 초안 — "(… 후 기입)" 칸은 정해지면 채웁니다.
> 근거: 역할 가이드 「2. 촬영 프로토콜·싱크」 7단계, 시험 녹화 (2026-10-05, 10-10)

---

## 1. 촬영 전 점검

촬영 날마다, 첫 에피소드 전에 확인합니다.

- [ ] 두 폰 배터리 80% 이상 (긴 촬영이면 충전기 연결)
- [ ] 저장 공간 — exo는 녹화 1분에 약 200 MB, ego는 약 140 MB. 촬영할 분량 × 2 이상 여유
- [ ] 두 폰 방해 금지 모드 켜기 (전화·알림이 오면 녹화가 끊길 수 있음)
- [ ] 삼각대 다리가 바닥 테이프 표시 위에 있음, 배치 사진과 같은 모습
- [ ] 조명 밝게 켜기 — 앱에 노출 설정이 없어서, 어두우면 손이 번져 보입니다
- [ ] 아래 카메라 설정 확인표를 두 폰 모두 확인
- [ ] 2절의 보정 영상 촬영 (그날 첫 촬영 전 1회) → 끝나면 체커보드를 치움

### 카메라 설정 확인표

모든 에피소드에서 같은 값을 씁니다.

| 항목 | ego (머리) | exo (삼각대) |
|---|---|---|
| 카메라 모델 | **iPhone 16** | **iPhone 18 Pro** (LiDAR 깊이가 필요해서 반드시 이 기기) |
| 거치 | 헤드 마운트 | 삼각대, **가로 방향** |
| 앱 | Spectacular Rec | Spectacular Rec |
| 해상도 | 1920×1440 (앱 기본값) | 1920×1440 (앱 기본값) |
| 프레임 속도 | 30 fps (앱 기본값) | 30 fps (앱 기본값) |
| 노출·셔터 | 앱에 설정 없음 → 조명으로 밝기 확보 | 같음 |
| Enable auto focus | 끔 | 끔 |
| Focus distance | (촬영 장소 결정 후 기입) | (촬영 장소 결정 후 기입) |
| 프레임별 시각 | 앱이 `data.jsonl`에 자동 기록 | 같음 |
| 소리 녹음 | 안 됨 (앱이 저장하지 않음, 정상) | 같음 |
| 저장 형식 | 앱이 만든 폴더 (`data.mov` + `data.jsonl` 등) | 같음 + 깊이 영상(`frames2/`) |

- **설정은 촬영 중 절대 바꾸지 않습니다.** 바꿔야 할 일이 생기면 멈추고 신서연에게 연락합니다.
- iPhone 16의 프레임 속도가 29.97로 기록되는 것은 정상입니다.

## 2. 카메라 설치

### exo (삼각대, iPhone 18 Pro)
1. 폰을 **가로**로 삼각대에 고정합니다. (세로로 거치하면 영상이 옆으로 누워 저장되어 손 인식이 어려워집니다)
2. 삼각대 다리를 바닥 테이프 표시에 맞춥니다. 배치 사진과 비교합니다.
3. 화면에 아래가 모두 들어오는지 확인합니다.
   - 작업 테이블 전체
   - 작업자의 어깨부터 손끝까지
   - 팔을 가장 멀리 뻗은 자세, 몸 쪽으로 바짝 당긴 자세 — 직접 해 보고 둘 다 화면 안
   - 손등과 손가락 뿌리가 보이는 각도
4. 위 조건을 지키는 선에서 테이블에 최대한 가깝게 둡니다. (멀수록 손이 작게 찍히고 깊이가 부정확해집니다)
5. 설치 후에는 삼각대와 폰을 건드리지 않습니다.

### ego (머리, iPhone 16)
1. 헤드 마운트에 iPhone 16을 끼웁니다.
2. 작업 자세에서 손과 테이블이 화면 가운데쯤 오도록 각도를 맞춥니다.

### 보정 영상 (촬영 날마다 첫 에피소드 전 1회)
1. 체커보드(한 칸 25 mm)를 테이블 위 테이프 표시 자리에 평평하게 놓습니다. 보드 위에 아무것도 올리지 않습니다.
2. exo로 3초 정도 녹화합니다.
3. **체커보드를 치웁니다.** 에피소드는 체커보드 없이 찍습니다. (보드가 깔려 있으면 손 인식이 흔들립니다)
4. 녹화 폴더 이름을 `CALIB_YYYYMMDD_HHMM_exo`로 바꿉니다. (예: `CALIB_20261020_1400_exo`)

---

## 3. 에피소드 진행 순서

모든 에피소드를 이 순서로 찍습니다.

1. **두 카메라 녹화 시작** — exo → ego 순서로 누르고, 둘 다 녹화 중인지 확인
2. **시작 박수** — 두 카메라에 모두 보이는 곳에서 한 번 크게 칩니다.
   - 박수 칠 때 머리(ego)는 손을 바라봅니다.
   - 두 손바닥이 닿는 순간이 선명하게 보여야 합니다. 손이 가려지면 다시 칩니다.
3. **초기 자세** — 1~2초 멈춤
4. **태스크 수행**
5. **종료 자세** — 1~2초 멈춤
6. **끝 박수** — 시작 박수와 같은 방법
7. **녹화 종료** — ego → exo 순서

- 박수를 빼먹었으면 그 에피소드는 **처음부터 다시 찍습니다.** 앱이 소리를 녹음하지 않아서, 박수 장면 없이는 두 영상을 맞출 방법이 없습니다.
- 태스크에 실패해도 **지우지 않습니다.** 기록지에 실패로 적고 다음 에피소드로 갑니다.

---

## 4. 파일 이름 규칙·저장

- **에피소드 ID:** `T{태스크번호}_E{세 자리 번호}` (예: `T2_E017`). 태스크마다 001부터 순서대로 매깁니다. 다시 찍은 에피소드도 새 번호를 받습니다.
- 녹화가 끝나면 앱이 만든 `recording_날짜_시각/` 폴더 이름을 바꿉니다. **폴더 안 파일은 그대로 둡니다.**
  - ego: `T2_E017_ego/`
  - exo: `T2_E017_exo/`
- 영상과 프레임별 시각은 폴더 안에 있습니다. 가이드의 파일 이름과는 아래처럼 대응합니다.

  | 가이드 이름 | 우리 폴더 안 |
  |---|---|
  | `T2_E017_ego.mp4` / `T2_E017_exo.mp4` | `T2_E017_ego/data.mov` / `T2_E017_exo/data.mov` |
  | 시각 파일 `T2_E017_ego_ts.csv` | `T2_E017_ego/data.jsonl` (프레임마다 `time`) |

  `.mp4`·`_ts.csv` 형식이 필요하면 신서연이 폴더에서 만들어 드립니다.
- 저장 위치: (팀 결정 후 기입)
- 영상과 폴더는 GitHub에 올리지 않습니다.

---

## 5. 촬영 기록지

에피소드마다 한 줄씩 적습니다. (형식: 팀 결정 후 기입)

| 에피소드 ID | 수집자 | 케이스 태그 | 촬영 시각 | 성공 여부 | 특이사항 |
|---|---|---|---|---|---|
| T2_E017 | 홍길동 | 빠른 동작\|가장자리 | 2026-10-20 14:05 | 1 | |

- 케이스 태그가 여러 개면 `|`로 잇습니다.
- 성공 여부: 1 = 성공, 0 = 실패
- 특이사항: 박수가 가려짐, 카메라가 움직임, 손이 가려진 장면 등

---

## 6. 카메라가 움직였을 때

삼각대나 exo 폰을 건드렸거나, 화면 구도가 배치 사진과 달라 보이면:

1. 촬영을 멈춥니다.
2. 삼각대를 테이프 표시에 다시 맞춥니다.
3. 2절 「보정 영상」을 다시 찍습니다.
4. 기록지 특이사항에 "카메라 이동, 보정 다시 함 (`CALIB_...` 폴더 이름)"을 적습니다.
5. 신서연에게 알립니다. (보정값 계산은 신서연이 합니다)

## 7. 시간 차 표 (`sync/sync.csv`)

촬영 후 신서연이 박수 장면으로 에피소드마다 두 영상의 시간 차를 계산해 채웁니다. 3번 담당은 가공할 때 이 표로 ego 값을 exo 시간축에 옮깁니다.

| 열 | 내용 |
|---|---|
| `episode_id` | 에피소드 ID |
| `offset_start_s` | 시작 시간 차 (s) = exo 시작 박수 시각 − ego 시작 박수 시각 |
| `offset_end_s` | 끝 시간 차 (s) = exo 끝 박수 시각 − ego 끝 박수 시각 |
| `drift_s` | 드리프트 (s) = 끝 시간 차 − 시작 시간 차 |
| `algo_offset_s` | 지난 학기 어긋남 검출 알고리즘의 추정치 (s), 없으면 빈칸 |
| `usable` | 사용 가능 여부 (1 또는 0) |
| `note` | 제외 이유 등 |

- 시각은 앱이 기록한 프레임별 시각(`data.jsonl`) 기준입니다. 두 폰의 프레임 속도가 조금 달라서 프레임 번호로는 맞추지 않습니다.
- `usable = 0`인 에피소드는 허용 기준을 넘은 것입니다. 재촬영하거나 가공에서 뺍니다.
