# 촬영 프로토콜

> 대상: 3번 수집·가공 담당 (1~7절, 이 문서만 보고 촬영할 수 있게) · 영상·키포인트·좌표를 다루는 모든 역할 (8절)
> 작성·문의: 신서연 (2. 촬영 프로토콜·싱크)
> 상태: **확정 (2026-11-04)** — 허용 기준 멘토 확인 완료, 본 촬영 T1~T3 기준으로 값 채움. 같은 날 `camera_setup.md`를 8절로 합침
> 근거: 역할 가이드 「2. 촬영 프로토콜·싱크」 7단계, 시험 녹화 (2026-10-05, 10-10, 10-13), 본 촬영 데이터 `~/data/raw/T1~T3`
> 싱크·보정 결과 파일 쓰는 법은 `sync/README.md`

## 1. 촬영 전 점검

촬영 날마다, 첫 에피소드 전에 확인합니다.

- [ ] 모든 폰 배터리 80% 이상 (긴 촬영이면 충전기 연결)
- [ ] 저장 공간 — exo는 녹화 1분에 약 200 MB, ego는 약 140 MB. 촬영할 분량 × 2 이상 여유
- [ ] 모든 폰 방해 금지 모드 켜기 (전화·알림이 오면 녹화가 끊길 수 있음)
- [ ] 삼각대 다리가 바닥 테이프 표시 위에 있음, 배치 사진과 같은 모습
- [ ] 조명 밝게 켜기 — 앱에 노출 설정이 없어서, 어두우면 손이 번져 보입니다
- [ ] 모든 폰 **화면 회전 잠금** 켜기, 삼각대에 끼우는 방향을 배치 사진과 같게 (8.2절)
- [ ] 아래 카메라 설정 확인표를 모든 폰에서 확인
- [ ] 2절의 보정 영상 촬영 (태스크마다 첫 에피소드 전 1회) → 끝나면 체커보드를 치움

> 지금 촬영 구성은 카메라 4대입니다: exo 3대(`exo_front` 정면 = 기준 카메라, `exo_left`, `exo_right`) + ego 1대. LiDAR 깊이(`frames2/`)는 `exo_right`에만 있습니다. left·right는 **작업자 기준**입니다.

### 카메라 설정 확인표

모든 에피소드에서 같은 값을 씁니다. 기기·해상도·fps는 본 촬영 T1~T3 데이터(`metadata.json`, `calibration.json`, `data.jsonl`)에서 확인한 값입니다.

| 항목 | `exo_front` (기준) | `exo_left` | `exo_right` | `ego` (머리) |
|---|---|---|---|---|
| 기기 (`device_model`) | iPhone18,5 | iPhone14,7 | iPhone19,2 (**LiDAR**) | iPhone17,3 (iPhone 16) |
| 거치 | 삼각대, **가로** | 삼각대, **가로** | 삼각대, **가로** | 헤드 마운트 |
| 앱 | Spectacular Rec | 같음 | 같음 | 같음 |
| 해상도 | 1920×1440 | 1920×1440 | 1920×1440 | 1920×1440 |
| 프레임 속도 | T1·T3 59.97 / T2 30.00 fps | 29.99 fps | 30.00 fps | 29.99 fps |
| 노출·셔터 | 앱에 설정 없음 → 조명으로 밝기 확보 (프레임마다 `exposureTimeSeconds` 기록됨) | 같음 | 같음 | 같음 |
| 초점 | Enable auto focus **끔** → 촬영 장소에서 맞춘 초점 고정 (값은 따로 기록되지 않음) | 같음 | 같음 | 같음 |
| 프레임별 시각 | 앱이 `data.jsonl`에 자동 기록 (`time`, 폰 부팅 기준 s) | 같음 | 같음 | 같음 |
| 소리 녹음 | 안 됨 (앱이 저장하지 않음, 정상) | 같음 | 같음 | 같음 |
| 저장 형식 | 앱이 만든 폴더 (`data.mov`, `data.jsonl`, `calibration.json`, `metadata.json`) | 같음 | 같음 + 깊이 `frames2/` | 같음 |

- **설정은 촬영 중 절대 바꾸지 않습니다.** 바꿔야 할 일이 생기면 멈추고 신서연에게 연락합니다.
- 폰마다 fps가 조금씩 달라도(29.99 / 30.00 / 59.97) 정상입니다. 싱크는 프레임 번호가 아니라 `data.jsonl` 프레임 시각으로 맞춥니다.

## 2. 카메라 설치

### exo (삼각대 3대: front · left · right)
1. 폰을 **가로**로 삼각대에 고정합니다. (세로로 거치하면 영상이 옆으로 누워 저장되어 손 인식이 어려워집니다)
2. 삼각대 다리를 바닥 테이프 표시에 맞춥니다. 배치 사진과 비교합니다.
3. 화면에 아래가 모두 들어오는지 확인합니다.
   - 작업 테이블 전체
   - 작업자의 어깨부터 손끝까지
   - 팔을 가장 멀리 뻗은 자세, 몸 쪽으로 바짝 당긴 자세 — 직접 해 보고 둘 다 화면 안
   - 손등과 손가락 뿌리가 보이는 각도
4. 위 조건을 지키는 선에서 테이블에 최대한 가깝게 둡니다. (멀수록 손이 작게 찍히고 깊이가 부정확해집니다)
5. 설치 후에는 삼각대와 폰을 건드리지 않습니다.

### ego (머리, iPhone 16)
1. 헤드 마운트에 iPhone 16을 끼웁니다.
2. 작업 자세에서 손과 테이블이 화면 가운데쯤 오도록 각도를 맞춥니다.

### 보정 영상 (태스크마다 첫 에피소드 전 1회)
1. 체커보드(한 칸 25 mm, 내부 코너 21×15)를 테이블 위 테이프 표시 자리에 평평하게 놓습니다. 보드 위에 아무것도 올리지 않습니다.
2. exo 3대로 3초 정도 녹화합니다. 세 화면 모두 보드 전체가 보여야 합니다.
3. **체커보드를 치웁니다.** 에피소드는 체커보드 없이 찍습니다. (보드가 깔려 있으면 손 인식이 흔들립니다)
4. 녹화 폴더 이름을 `T{태스크번호}_check`로 바꿉니다. (예: `T2_check`, 같은 태스크 안에서 다시 찍으면 `T2_check2`)

## 3. 에피소드 진행 순서

모든 에피소드를 이 순서로 찍습니다.

1. **모든 카메라 녹화 시작** — exo 3대 → ego 순서로 누르고, 모두 녹화 중인지 확인
2. **시작 박수** — 모든 카메라에 보이는 곳에서 한 번 크게 칩니다.
   - 박수 칠 때 머리(ego)는 손을 바라봅니다.
   - **빠르게 쳐서** 두 손바닥이 닿는 순간이 선명하게 보여야 합니다. 천천히 손을 모으거나 맞잡으면 자동 검출이 안 됩니다 (T2·T3에서 확인). 손이 가려지면 다시 칩니다.
3. **초기 자세** — 1~2초 멈춤
4. **태스크 수행**
5. **종료 자세** — 1~2초 멈춤
6. **끝 박수** — 시작 박수와 같은 방법
7. **녹화 종료** — ego → exo 순서

- 박수를 빼먹었으면 그 에피소드는 **처음부터 다시 찍습니다.** 앱이 소리를 녹음하지 않아서 박수가 시간 맞추기의 기준입니다. (박수 없는 에피소드도 7절 시계 모델로 채울 수는 있지만, 기준점이 되는 다른 에피소드의 박수가 필요합니다)
- 태스크에 실패해도 **지우지 않습니다.** 기록지에 실패로 적고 다음 에피소드로 갑니다.

## 4. 파일 이름 규칙·저장

- **에피소드 ID:** `T{태스크번호}_E{세 자리 번호}` (예: `T2_E017`). 태스크마다 001부터 순서대로 매깁니다. 다시 찍은 에피소드도 새 번호를 받습니다.
- 녹화가 끝나면 폰마다 앱이 만든 `recording_날짜_시각/` 폴더 이름을 **에피소드 ID 그대로** 바꿉니다 (예: `T2_E017/`). 체커보드 영상은 `T2_check/`. **폴더 안 파일은 그대로 둡니다.**
- 카메라는 폰(폴더 묶음)으로 구분합니다. 올릴 때 카메라별로 모아 `T2_exo_front.zip`처럼 묶습니다.
- **저장 위치 (GPU 서버):**

  ```
  ~/data/raw/T{태스크}/{exo_front, exo_left, exo_right, ego}/T{태스크}_E###/   data.mov, data.jsonl, calibration.json, metadata.json (+ frames2/ : exo_right)
  ~/data/raw/T{태스크}/{exo_front, exo_left, exo_right}/T{태스크}_check/         체커보드 보정 영상
  ~/data/staging/T{태스크}_{카메라}.zip                                            올린 원본 zip
  ```
  원본은 읽기 전용으로 씁니다 (이름 변경·삭제·덮어쓰기 금지). 가공 결과는 `~/out/본인이름/`.
- 가이드의 파일 이름과는 아래처럼 대응합니다.

  | 가이드 이름 | 우리 폴더 |
  |---|---|
  | `T2_E017_ego.mp4` / `T2_E017_exo.mp4` | `ego/T2_E017/data.mov` / `exo_front/T2_E017/data.mov` (exo는 front·left·right 3개) |
  | 시각 파일 `T2_E017_ego_ts.csv` | `ego/T2_E017/data.jsonl` (프레임마다 `time`) |

  `.mp4`·`_ts.csv` 형식이 필요하면 신서연이 폴더에서 만들어 드립니다.
- 영상과 폴더는 GitHub에 올리지 않습니다.

## 5. 촬영 기록지

기록 형식은 3번이 정한 것을 따릅니다.

- **촬영 계획표** (촬영 전): `episodes/tools/plan.py` 양식 — 열 `id_start, id_end, task, layout, speed, case_tags, purpose` (예: `T1_E001, T1_E015, 컵 잡기, 보통 거리, 보통, 정밀 구간, 학습`). `python plan.py check plan.csv`로 케이스 편중 검사
- **에피소드별 기록** (촬영 후): 에피소드마다 아래 항목을 남기고, 3번이 가공할 때 `meta.json`(`collector`, `case_tags` 등)으로 옮깁니다.

| 에피소드 ID | 수집자 | 케이스 태그 | 촬영 시각 | 성공 여부 | 특이사항 |
|---|---|---|---|---|---|
| T2_E017 | 홍길동 | 빠른 동작\|가장자리 | 2026-10-20 14:05 | 1 | |

- 케이스 태그는 `큰 이동`, `정밀 구간`, `가장자리`, `빠른 동작` 중에서 고릅니다 (`episodes/tools/constants.py`). 여러 개면 `|`로 잇습니다.
- 성공 여부: 1 = 성공, 0 = 실패
- 특이사항: 박수가 가려짐, 카메라가 움직임(6절), 손이 가려진 장면 등

## 6. 카메라가 움직였을 때

삼각대나 exo 폰을 건드렸거나, 화면 구도가 배치 사진과 달라 보이면:

1. 촬영을 멈춥니다.
2. 삼각대를 테이프 표시에 다시 맞춥니다.
3. 2절 「보정 영상」을 다시 찍습니다.
4. 기록지 특이사항에 "카메라 이동, 보정 다시 함 (`T2_check2` 등 폴더 이름, 몇 번째 에피소드부터)"을 적습니다. 폰을 삼각대에 다시 끼운 경우도 같습니다.
5. 신서연에게 알립니다. (보정값 계산은 신서연이 합니다)

## 7. 시간 차 표 (`sync/sync.csv`)

촬영 후 신서연이 박수 장면으로 에피소드마다 카메라 사이 시간 차를 계산해 채웁니다. 3번 담당은 가공할 때 이 표로 각 카메라 값을 기준 카메라 시간축에 옮깁니다 (`episodes/tools/io_utils.read_sync_row`가 이 표를 읽음).

- **기준 카메라 = 정면 exo (`exo_front`).** 기준 카메라 자신은 행이 없습니다.
- **에피소드 × 카메라마다 한 행** (`camera` = `left`, `right`, `ego`). 그날 찍지 않은 카메라는 행이 없습니다.

| 열 | 내용 |
|---|---|
| `episode_id` | 에피소드 ID |
| `camera` | 기준 카메라에 맞출 카메라 (`left` / `right` / `ego`) |
| `offset_start_s` | 시작 시간 차 (s) = 기준 카메라 시작 박수 시각 − 이 카메라 시작 박수 시각 |
| `offset_end_s` | 끝 시간 차 (s) = 기준 카메라 끝 박수 시각 − 이 카메라 끝 박수 시각 |
| `drift_s` | 드리프트 (s) = 끝 시간 차 − 시작 시간 차 |
| `s0` | 이 카메라 자기 시각으로 잰 시작 박수 시각 (s) |
| `s1` | 이 카메라 자기 시각으로 잰 끝 박수 시각 (s) |
| `usable` | 사용 가능 여부 (1 또는 0) |
| `note` | 제외 이유, 안내 검출 여부, 박수 프레임 번호 등 |

- 시각은 앱이 기록한 프레임별 시각(`data.jsonl`) 기준입니다. 폰마다 프레임 속도가 달라서(30 / 60 fps) 프레임 번호로는 맞추지 않습니다. 폰 시계는 부팅 후 경과 시간이라 카메라마다 기준이 다르고, 그래서 시간 차가 수만 초로 나올 수 있습니다 (정상).
- 이 카메라 시각 `t`를 기준 카메라 시각으로: `t + offset_start_s + drift_s × (t − s0) / (s1 − s0)` (드리프트는 시작·끝 박수 사이 선형).
- 박수 시각은 `sync/detect_claps.py`로 찾고 `sync/make_sync_csv.py`로 표를 만듭니다. 정밀도는 각 카메라 약 ±1프레임 (30 fps 33 ms, 60 fps 17 ms).
- **허용 기준 (멘토 확인, 2026-11-04):**
  - 박수 행은 에피소드 안 드리프트 |`drift_s`| ≤ 1프레임(0.034 s)일 때만 씁니다. 수십 초 동안 실제 드리프트는 1 ms 미만이라, 더 크면 박수를 잘못 잡은 것으로 보고 시계 모델 값으로 바꿉니다.
  - 박수 또는 시계 모델로 시간 차가 정해진 행은 `usable = 1`. 시계 모델 행은 검증(LOO) 오차를 `note`에 남깁니다. 본 촬영 T1~T3는 675행 모두 `usable = 1`, 검증 오차 최대 36 ms (약 1프레임).
  - `usable = 0`: 폴더가 없거나, 그 세션 구간에 기준점(믿을 수 있는 박수)이 하나도 없을 때. 재촬영하거나 가공에서 뺍니다.
- **영상 기반 자동 정렬과의 비교 (가이드 5단계):** 영상 움직임만으로 자동 정렬하면 박수 기준과 60~260 ms 차이 났고 (10/13 시험, 9쌍), 손 움직임 신호 상호상관도 1프레임 안에 맞는 비율이 8~78%였습니다 (11/04, T1). 그래서 박수 + 시계 모델로 가고, 가이드의 `algo_offset_s` 열은 두지 않습니다.

### 박수를 못 찾은 에피소드: 세션 시계 모델 (2026-11-04 추가)

- 폰 시계 차는 폰이 잠들지 않는 한 한 촬영 세션 안에서 거의 일정합니다 (T1 31분 동안 기울기 0.6~12.5 ppm).
  그래서 믿을 수 있는 박수(기준점)로 카메라마다 "시계 차 = a + b × 기준 시각" 직선을 맞추고, 박수가 없거나 틀린 행을 이 직선으로 채웁니다 (`sync/fit_clock.py`).
- 기준점: 박수 행 중 |`drift_s`| ≤ 1프레임(0.034 s)인 것. 에피소드 길이 안의 실제 드리프트는 1 ms 미만이라, 그보다 크면 시작·끝 중 하나를 잘못 잡은 것으로 봅니다.
  박수 자동 검출이 거의 안 되는 태스크(T2·T3)는 `sync/label_sheets.py` 그림을 보고 에피소드 몇 개의 박수 프레임을 손으로 표시해 기준점을 만듭니다 (`--manual`, 표는 서버 `~/out/신서연/label_T{n}/manual_T{n}.csv`).
- 녹화 시작 시각 차이가 3 s 넘게 바뀌면(폰이 잠든 것) 구간을 나눠 따로 맞춥니다. 기준점이 없는 구간은 `usable=0`.
- `note` 앞머리: `박수` = 박수 값 그대로 (모델과의 차이 표시), `시계 모델` = 모델 값 (s0·s1 = 이 카메라 첫·마지막 프레임 시각, 기준점 수와 LOO 95% 오차 표시). 읽는 법(`read_sync_row`)은 같습니다.
- 검증: 기준점 에피소드를 하나씩 빼고 예측한 오차(LOO) 최대 T1 29 ms, T2 36 ms, T3 36 ms.
- 실행 순서: `run_task.sh` (박수) → `fit_clock.py` (빈 행 채우기). 태스크마다 `exo_calib_T{n}.json`을 따로 둡니다 (체커보드 `T{n}_check`).

## 8. 영상 방향 · 카메라 배치 · 보정 규칙 (구 `camera_setup.md`)

> 대상: 영상·키포인트·좌표를 다루는 모든 역할 (3번 가공, 4번 리타게팅, 6번 RLDS, 7·8번 학습·평가). 2026-11-04 결정

### 8.1 영상은 "저장된 그대로" 읽는다

폰은 녹화를 시작할 때 기울기를 보고 "보여 줄 때 이만큼 돌려라"는 회전 꼬리표(0/90/180/270)를 영상에 적는데, 이 꼬리표는 믿을 수 없습니다.

| 예전 영상 (10/19·11/03) | 꼬리표 | 저장된 화면 | |
|---|---|---|---|
| 10/19 exo_left (하루 종일 같은 자리) | 0 · 180 · 270 섞임 | 모두 같은 화면 | 꼬리표가 틀림 |
| 11/03 exo_right T1 | 180 | 거꾸로 | 꼬리표가 맞음 |
| 11/03 exo_front T2 일부 | 0 | 거꾸로 (폰을 뒤집어 끼움) | 꼬리표가 틀림 |

- 프로그램마다 꼬리표 처리도 다릅니다 (QuickTime·맥 opencv 5.0은 꼬리표대로 돌리고, 서버 `episodes` 환경 opencv 4.11은 무시). 같은 파일이 컴퓨터마다 다르게 보입니다.
- 앱이 기록한 카메라 내부 파라미터 K(`calibration.json`, `data.jsonl`)와 보정 K·R·t, 깊이 `frames2/`는 모두 **저장된 화면(1920×1440) 기준**입니다.

```python
import cv2
cap = cv2.VideoCapture("data.mov")
cap.set(cv2.CAP_PROP_ORIENTATION_AUTO, 0)   # 꼭 명시 (opencv 버전마다 기본값이 다름)
```
- ffmpeg로 프레임을 뽑을 때도 자동 회전을 끕니다: `ffmpeg -noautorotate -i data.mov ...`
- 지금 서버 데이터(`~/data/raw/T1~T3`)는 회전 없이 저장된 그대로 처리했습니다 (싱크·보정).

### 8.2 거꾸로 찍힌 영상

- 화면이 서 있어야 하는 곳(손·자세 인식, 눈으로 보는 그림, OpenVLA 학습 이미지)에서만 **메모리에서** 180° 돌립니다. 원본 파일은 고치지 않습니다.
- 키포인트·궤적 파일에는 **저장된 화면 좌표**로 되돌려 넣습니다 (보정 K·R·t와 같은 기준이어야 3D 계산이 맞음).

```python
img = cv2.rotate(frame, cv2.ROTATE_180)              # 거꾸로인 영상만
# ... img 에서 손 인식 -> (u_, v_) ...
u, v = W - 1 - u_, H - 1 - v_                        # 저장할 때 되돌림 (W=1920, H=1440)
```
- 180° 회전은 거울 반전이 아니라서 왼손·오른손 구분은 바뀌지 않습니다.
- 카메라가 거꾸로인 것 자체는 3D 계산에 문제가 없습니다 (K·R·t가 그 방향을 그대로 담음).
- 다음 촬영부터는 1절대로 화면 회전 잠금을 켜고 끼우는 방향을 맞춰서 거꾸로 찍히지 않게 합니다.

### 8.3 보정은 "배치" 단위

- **배치** = 카메라가 한 자리에 고정돼 있던 구간. 폰을 다시 끼우거나 삼각대를 옮기면 새 배치이고, 체커보드 영상을 다시 찍어야 합니다 (2절, 6절).
- 지금 데이터는 태스크마다 체커보드(`T{n}_check`)가 있어서 **`sync/exo_calib_T{n}.json`** 을 씁니다. 에피소드 ID의 태스크 번호로 고릅니다 (`T2_E017` → `exo_calib_T2.json`).
- 형식은 3번 `episodes/tools/multiview.load_calibs`와 같습니다: `{"ref_camera": "front", "cameras": {"front": {K, R, t, dist}, "left": …, "right": …}}`, `p_cam = R @ p_table + t` (m).
- ego는 머리와 함께 움직여서 보정하지 않습니다.

**테이블 좌표계 (2번 정의)**
- 원점: 체커보드 내부 코너 중 front에서 가장 가까운 줄의 가장 왼쪽
- x: front에서 볼 때 오른쪽 / y: front에서 멀어지는 쪽(작업자 쪽) / z: 위 / 단위 m
- 카메라 이름 left·right는 **작업자 기준**입니다 (exo_left = front에서 볼 때 오른쪽에 있는 카메라).
