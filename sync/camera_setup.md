## 0. 한눈에

1. **영상은 항상 "저장된 그대로" 읽는다.** 폰이 적는 회전 꼬리표(0/90/180/270)는 무시한다.
2. **거꾸로 찍힌 영상은 `upright_rot` 표를 보고 메모리에서만 세운다.** 원본 파일은 고치지 않는다. 좌표는 저장 화면 기준으로 되돌려 저장한다.
3. **보정(카메라 위치)은 날짜가 아니라 "배치" 단위.** 폰을 다시 끼우면 새 배치다. 체커보드가 없는 배치는 다른 카메라와 손 키포인트로 추정한다 (아래 4절).

## 1. 왜 이렇게 하나

폰은 녹화를 시작할 때 기울기를 보고 "보여 줄 때 이만큼 돌려라"는 꼬리표를 영상에 적는다. 이 꼬리표를 믿을 수 없다.

| 영상 | 꼬리표 | 저장된 화면 | |
|---|---|---|---|
| 10/19 exo_left (같은 삼각대, 하루 종일 같은 자리) | 0 · 180 · 270 섞임 | 모두 같은 화면 | 꼬리표가 틀림 |
| 11/03 exo_right T1 | 180 | 거꾸로 | 꼬리표가 맞음 |
| 11/03 exo_front T2_E006–E045 | **0** | **거꾸로** (폰을 뒤집어 끼움) | 꼬리표가 틀림 |

- 프로그램마다 꼬리표 처리가 다르다. QuickTime·맥 opencv 5.0은 꼬리표대로 돌려 보여 주고, 서버 `episodes` 환경 opencv 4.11은 무시한다. 같은 파일이 컴퓨터마다 다르게 보인다.
- 앱이 기록한 카메라 내부 파라미터 K(`calibration.json`, `data.jsonl`)는 **저장된 화면 기준**이다.
- 그래서 "저장된 화면" 하나로 통일하고, 세워야 할 때만 표를 보고 돌린다.

## 2. 규칙 1 — 저장된 그대로 읽기

```python
import cv2
cap = cv2.VideoCapture("data.mov")
cap.set(cv2.CAP_PROP_ORIENTATION_AUTO, 0)   # 꼭 명시 (opencv 버전마다 기본값이 다름)
```

- 모든 픽셀 좌표(키포인트, 보정 K·R·t, 깊이 `frames2/`)는 이 화면(1920×1440) 기준이다.
- ffmpeg로 프레임을 뽑을 때도 자동 회전을 끈다: `ffmpeg -noautorotate -i data.mov ...`

## 3. 규칙 2 — `upright_rot` (거꾸로 찍힌 영상 세우기)

### 표: `sync/upright_<날짜>.csv` (예: `sync/upright_20261103.csv`)

| 열 | 내용 |
|---|---|
| `date` | 촬영 날짜 폴더 (`2026-11-03`) |
| `camera` | `ego` / `exo_front` / `exo_left` / `exo_right` |
| `folder` | 에피소드 ID 또는 `<MMDD>_check` 등 폴더 이름 |
| `tag_rot` | 영상의 회전 꼬리표 (참고용, **쓰지 않음**) |
| `upright_rot` | 저장 화면을 시계 방향으로 이만큼 돌리면 똑바로 선다 (0 또는 180). 빈칸 = 판단 못 함 |
| `votes_0`, `votes_180`, `method`, `note` | 판단 근거 |

### 판단 방법 (`sync/orientation.py`)
- 영상마다 프레임 5장을 저장된 그대로 읽고, 그대로 / 180° 돌려서 MediaPipe로 인식한다.
  - exo: 사람 자세 — 코가 두 어깨보다 위에 있는 방향에 1표
  - ego: 손 — 손목이 손가락 뿌리보다 아래에 있는 방향에 1표 (머리 카메라에서 손은 아래에서 들어옴)
- 표가 많은 쪽이 `upright_rot`. 비기거나 표가 적으면 `note`에 표시하고 대표 프레임을 눈으로 확인해 고친다.
- 시험: 답을 아는 영상 22개 모두 맞음 (꼬리표 0인데 실제로 거꾸로인 front T2_E006도 180으로 잡음).

### 쓰는 법
화면이 서 있어야 하는 곳에서만 돌린다: **손·자세 인식(MediaPipe), 눈으로 보는 그림, OpenVLA 학습 이미지.**

```python
ROT = {0: None, 180: cv2.ROTATE_180}
img = frame if ROT[r] is None else cv2.rotate(frame, ROT[r])     # r = upright_rot
# ... img 에서 손 인식 -> (u', v') 픽셀 ...
# 저장할 때는 저장 화면 좌표로 되돌린다 (W=1920, H=1440)
u, v = (u_, v_) if r == 0 else (W - 1 - u_, H - 1 - v_)
```

- 180° 회전은 거울 반전이 아니므로 **왼손·오른손 구분은 바뀌지 않는다.**
- 키포인트·궤적 파일에는 **저장 화면 좌표**만 넣는다 (보정 K·R·t와 같은 기준이어야 3D 계산이 맞음).
- 학습 이미지(6번 RLDS)는 `upright_rot`만큼 돌린 이미지를 넣는다 (모델 입력은 똑바로 선 화면).
- 카메라가 거꾸로인 것 자체는 3D 계산에 문제가 없다. K·R·t가 그 방향을 그대로 담고 있다.

### 데이터로 추정하는 방법 (체커보드가 없는 배치)
기준: 체커보드로 보정된 카메라 하나 이상 + 같은 장면의 손 키포인트 (박수로 시간을 맞춘 뒤).

1. **right 배치 B**: right LiDAR 깊이(`frames2/`)로 손 키포인트의 3D 위치(right 카메라 기준, m)를 구하고, 같은 순간 보정된 left 화면의 같은 키포인트에 맞춘다 (PnP + RANSAC). 깊이가 미터 단위라 크기도 정해진다.
2. **front 배치 B·C**: left + right(1에서 구함)로 손 키포인트를 삼각측량해 테이블 좌표 3D를 만들고, front 화면에 맞춘다 (PnP + RANSAC). C는 T1 보정을 그대로 썼을 때의 오차도 비교한다.
3. **함께 미세 조정**: left는 고정하고 나머지 카메라와 3D 점을 재투영 오차가 최소가 되게 조정한다.
4. **검증 (필수)**: 체커보드가 있는 11/03 T1에서 right·front 보정을 모른다고 치고 같은 방법으로 추정 → 체커보드 보정값과 비교해 위치·각도 오차를 기록한다. 추정 배치의 결과에는 이 오차와 에피소드별 재투영 오차를 함께 적는다.
5. 허용 기준(재투영 오차·위치 오차)은 4의 결과를 보고 멘토와 정한다. 기준을 넘는 카메라는 그 배치에서 3D 계산에 쓰지 않는다 (실패는 지우지 않고 기록).

### 파일
- **보정 파일: `sync/exo_calib/<날짜>_<묶음>.json`** — 세 exo 카메라의 배치가 모두 같은 에피소드 묶음마다 하나. 형식은 3번 `multiview.load_calibs`와 같다 (`{"ref_camera": "front", "cameras": {"front": {K, R, t, dist}, ...}}`, `pc = R @ p + t`, m).
  - 11/03은 묶음 3개: T1 (front A·left A·right A), T2_E006–E045 (front B·left A·right B), T2_E046–T3_E035 (front C·left A·right B)
  - 10/19는 묶음 1개 (front A·left A)
  - 카메라마다 `method` (`board` / `estimated`), 검증 오차, 출처를 함께 적는다.
- **배치 표: `sync/setups.csv`** — 에피소드마다 어느 보정 파일을 쓰는지.

| 열 | 내용 |
|---|---|
| `date`, `episode_id` | |
| `calib_file` | `sync/exo_calib/` 안의 파일 이름 |
| `front_setup`, `left_setup`, `right_setup` | 위 표의 배치 이름 |
| `note` | 예: front 영상 없음 (`11/03 T1_E074`) |

### 테이블 좌표계 (2번 정의)
- 원점: 체커보드 내부 코너 중 front에서 가장 가까운 줄의 가장 왼쪽 / x: front에서 볼 때 오른쪽 / y: front에서 멀어지는 쪽(작업자 쪽) / z: 위 / 단위 m
- 카메라 이름 left·right는 **작업자 기준**이다 (exo_left = front에서 볼 때 오른쪽에 있는 카메라).
- 체커보드가 없는 배치도 같은 테이블 좌표계로 추정된다 (left를 기준으로 붙이므로).
