# 지표 정의서

> 담당: 신서연 (5-2. 지표 계산)
> 상태: **v0.2 (2026-11-05)** — 멘토 답 반영(10월 3주 미팅). 10절에 남은 항목을 정하면 **고정**하고, 그 뒤로는 결과를 보기 전과 같은 정의만 씁니다.
> 근거: 역할 가이드 「5-2. 지표 계산」 1단계, 학생 안내서 5-1·5-3

## 0. 원칙

1. **정의는 결과를 보기 전에 고정합니다.** 결과를 본 뒤 정의를 바꾸면 특정 알고리즘에 유리하게 바꿨다는 의심을 피할 수 없습니다.
2. 정의를 바꿔야 하면 9절 변경 기록에 이유를 적고, **모든 알고리즘·모든 에피소드에 다시 적용**합니다.
3. 모든 지표는 **에피소드 하나 × 알고리즘 하나** 단위로 계산합니다.
4. 모든 지표는 **낮을수록 좋습니다.**
5. **실패를 지우지 않습니다.** IK 실패 프레임, 키포인트 누락 프레임도 그대로 포함해 계산합니다.
6. 같은 에피소드는 모든 알고리즘에서 같은 프레임 구간을 씁니다. 에피소드를 빼는 기준(8절)도 모든 알고리즘에 똑같이 적용합니다.

## 1. 입력

| 기호 | 내용 | 출처 |
|---|---|---|
| `q` | (T, 7) 팔 관절 각도, rad | 4번 `retarget/<알고리즘>/<에피소드ID>.npz` |
| `saturated` | (T, 7) 관절이 한계에 걸려 값이 잘렸는지 (bool) | 4번 npz |
| `status` | (T,) IK 상태 코드. 0 = 성공, 1 = 미수렴, 2 = 해 없음 | 4번 npz |
| (`gripper`) | 쓰지 않음. 그리퍼를 붙이지 않기로 해서(2026-11-03) 4번 npz에 있어도 지표 계산에 넣지 않습니다 | — |
| `pos_err` | (T,) 목표와 TCP의 위치 오차, m (4번 `tcp_error`) | 4번 npz |
| `lo`, `hi` | (7,) 관절 하한·상한, rad | 1번 `robot/joint_limits.csv` (`lower_rad`, `upper_rad`) |
| `tcp_pos`, `contacts` | 프레임별 TCP 위치(m, 로봇 베이스 좌표), 접촉 목록 | 5-1번 `replay(q)` |
| `ts` | (T,) exo_front 프레임 시각, s (저크의 Δt 계산용, 2.6절) | 3번 `episodes/<ID>/exo_ts.csv` |
| `g` | 파지 프레임의 배열 인덱스 = `grasp_frame − exo_start_frame` | 3번 `labels.json` (2.7절) |
| `kp` | (T, 7, 3) 테이블 좌표계 키포인트, m. exo 3대(front·left·right) 삼각측량 + 보정 후 값 | 3번 `episodes/<ID>/keypoints.npy`, 이름은 `keypoint_names.json` |
| 장애물 | 테이블 좌표계 박스(테이블·방해물·아크릴 판) | 3번 `obstacles.json` (`episodes/tools/obstacles.py`) → 5-1 재생 장면 (2.9절) |

- 배열 길이 `T = exo_end_frame − exo_start_frame`(끝 미포함)입니다. 프레임 축은 **exo_front 시간축**이고, 4번 배열과 3번 키포인트가 같은 축을 씁니다 (`episodes/DATA_STRUCTURE.md` 4절).
- 관절 한계는 1번 `robot/joint_limits.csv`의 `lower_rad`, `upper_rad`를 씁니다 (iiwa14: joint1·3·5 ±2.96706, joint2·4·6 ±2.09440, joint7 ±3.05433 rad).

## 2. 지표

### 2.1 관절 한계 위반율 (`limit_violation_rate`)

- **계산:** 어느 한 관절이라도 한계를 `ε = 1e-6 rad` 넘게 벗어난 프레임 수 ÷ 전체 프레임 수
  ```
  viol[t] = any_j ( q[t,j] < lo[j] − ε  or  q[t,j] > hi[j] + ε )
  limit_violation_rate = mean_t viol[t]
  ```
- **단위:** 비율 (0~1)
- `ε`는 수치 오차를 빼기 위한 값입니다.

### 2.2 관절 한계 포화율 (`limit_saturation_rate`) — 보조

- **계산:** 어느 한 관절이라도 `saturated`가 참인 프레임 수 ÷ 전체 프레임 수
- **단위:** 비율
- **따로 두는 이유:** 알고리즘 A(DLS)는 한계 밖 값을 계산 뒤에 잘라내므로 최종 출력의 한계 위반율이 항상 0입니다. 대신 목표를 못 따라간 흔적이 포화율에 남습니다. 이 지표가 없으면 A가 한계 처리에서 부당하게 좋아 보입니다.
- 한계를 제약으로 푸는 알고리즘(B mink)은 잘라내는 단계가 없으므로 4번이 `saturated`를 어떻게 채우는지 확인이 필요합니다 (10절).

### 2.3 자기 충돌률 (`self_collision_rate`)

- **계산:** 로봇 몸체끼리의 접촉 중 거리가 음수(파고듦)인 쌍이 하나라도 있는 프레임 수 ÷ 전체 프레임 수
  ```
  depth[t] = min( {d : (b1, b2, d) ∈ contacts[t], b1·b2 모두 로봇 몸체}, 기본값 0 )
  self_collision_rate = mean_t ( depth[t] < 0 )
  ```
- **단위:** 비율
- **검출 조건:** 5-1번 `replay/collision_exclude.md`에서 확정한 제외 쌍을 뺀 상태로 계산합니다. 제외 목록은 이 지표 값을 바꾸므로 **결과를 보기 전에 확정**합니다.
  - 제외 쌍은 **2개: `base`–`link1`, `link5`–`link7`**. `robot/robot.xml` 원본의 7쌍을 정상 자세로 재생해 검토했고, 나머지 5쌍은 닿지 않아 검사에 넣습니다 (`replay/collision_exclude.md`). 멘토: 원본 그대로도 되고, 검토할 수 있으면 하는 게 좋음 (Q4).
- **해석 시 주의:** 충돌 형상이 링크마다 구(sphere) 여러 개로 근사돼 있어, 실제 외형보다 넓거나 좁게 잡히는 곳이 있습니다. 모든 알고리즘에 같은 조건이라 비교는 유효하고, 절대값을 해석할 때 이 조건을 함께 적습니다.

### 2.4 최대 침투 깊이 (`max_penetration_m`)

- **계산:** 모든 프레임에서 가장 깊게 파고든 로봇 자기 접촉의 깊이. 충돌이 없으면 0
  ```
  max_penetration_m = −min_t depth[t]   (모든 depth[t] ≥ 0 이면 0)
  ```
- **단위:** m

### 2.5 IK 실패율 (`ik_failure_rate`, `ik_not_converged_rate`, `ik_no_solution_rate`)

- **계산:**
  ```
  ik_failure_rate       = mean_t ( status[t] ≠ 0 )
  ik_not_converged_rate = mean_t ( status[t] = 1 )
  ik_no_solution_rate   = mean_t ( status[t] = 2 )
  ```
- **단위:** 비율
- 실패 프레임에서 각 알고리즘이 무엇을 내놓는지(직전 자세 유지 등)는 4번 공통 규칙을 따르며, 그 값도 다른 지표 계산에 그대로 포함합니다.
- **해가 없을 때는 알고리즘별 방식을 그대로 씁니다** (멘토, Q11). 특정 알고리즘에만 재탐색(예: C의 팔꿈치 각도를 바꿔 다시 풀기)이나 보정 규칙을 덧붙이지 않습니다. 각 알고리즘의 출력이 상태 0·1·2 중 무엇에 해당하는지는 4번이 알고리즘마다 `config.json`에 적고, 이 지표는 그 `status`를 그대로 셉니다.

### 2.6 저크 RMS (`jerk_rms`)

- **계산:** **30 Hz로 맞춘 궤적**에서 관절 각도의 3차 차분 ÷ Δt³의 제곱평균제곱근. 7개 관절과 모든 프레임을 한꺼번에 평균합니다.
  ```
  # 30 Hz로 맞추기 (보간·스무딩 없이 프레임만 고름)
  k  = round( (1/30) / median(diff(ts)) )        # 60 fps 에피소드 → 2, 30 fps 에피소드 → 1
  q  = q[::k],  ts = ts[::k]                     # 첫 프레임부터 k칸마다
  Δt = median(diff(ts))                          # 실제 간격 (≈ 1/30 s)
  jerk[t,j] = ( q[t+3,j] − 3·q[t+2,j] + 3·q[t+1,j] − q[t,j] ) / Δt³      (t = 0 … T−4)
  jerk_rms  = sqrt( mean_{t,j} jerk[t,j]² )
  ```
- **단위:** rad/s³
- **30 Hz로 맞추는 이유:** 기준 시간축 exo_front가 본 촬영에서 **T1·T3 59.97 fps, T2 30.00 fps**입니다 (`sync/protocol.md`). 저크는 Δt³로 나누므로 fps에 크게 좌우됩니다 (같은 키포인트 노이즈가 60 fps에서 약 8배). 그대로 섞으면 케이스 칸에 태스크가 섞일 때 값의 크기를 비교할 수 없어서, 모든 에피소드를 30 Hz로 맞춥니다 (2026-11-05 결정).
- 고르는 것은 저크 계산에만 씁니다. 다른 지표는 모든 프레임으로 계산합니다.
- **한계:** 60 fps 에피소드에서 버려진 프레임에만 생긴 짧은 튐은 저크에 안 잡힙니다. 그런 튐은 IK 실패율·한계 위반율 등 모든 프레임으로 계산하는 지표에는 남습니다.
- `Δt`가 1/30 s와 0.1% 넘게 다른 에피소드는 `summary.md`에 표시합니다.
- IK 실패 프레임도 포함합니다. 실패 때문에 궤적이 튀는 것도 알고리즘의 특성입니다.

### 2.7 파지점 거리 (`grasp_dist_m`)

- **계산:** 파지 프레임 `g`에서 로봇 TCP와 사람 파지점(로봇 좌표로 옮긴 것) 사이 거리
  ```
  p_human = to_robot_point( (kp[g, thumb_tip] + kp[g, index_tip]) / 2 )
  grasp_dist_m = ‖ tcp_pos[g] − p_human ‖
  ```
- **단위:** m
- **사람 파지점:** 가이드대로 엄지 끝(`thumb_tip`)·검지 끝(`index_tip`)의 중점입니다. 3D는 exo 3대(front·left·right) 삼각측량 값(`keypoints.npy`)을 씁니다. 멘토: 폰 3대면 안 보이는 곳이 없어져 손가락 끝 깊이 문제가 사라짐 (Q2). 그래서 손등 기준점으로 바꾸지 않습니다.
- **파지 프레임 인덱스:** `labels.json`의 프레임 번호는 exo_front 영상 전체 기준, 4번 배열은 에피소드 구간만 담습니다.
  ```
  g = grasp_frame − exo_start_frame
  ```
  하나만 틀려도 이 지표 전체가 틀리므로, 파일럿 에피소드에서 5-1번 나란히 보기 영상의 `g` 프레임이 실제로 잡는 순간인지 확인합니다.
- **파지가 여러 번인 에피소드:** 첫 번째 파지만 씁니다. 3번 라벨 규칙의 `grasp_frame`이 "물체를 완전히 쥔 첫 프레임" 하나라서 그대로 맞습니다. 멘토: 첫 파지만이 효율적 (Q3).
- `kp[g]`의 엄지 끝·검지 끝 중 하나라도 NaN이면 그 에피소드의 파지점 거리는 NaN으로 두고 이 지표에서만 뺍니다 (8절). 다른 프레임 값으로 메우지 않습니다.
- **TCP:** 플랜지(`attachment_site`, 팔 끝 장착면). 그리퍼를 쓰지 않기로 해서(2026-11-03) 플랜지를 TCP로 씁니다.
- **해석 시 주의:** 로봇 목표는 사람 손목에서 만들고 파지점은 손가락 쪽에 있으므로, 완벽하게 따라가도 0이 되지 않습니다. TCP가 손가락 끝이 아니라 플랜지라서 이 편향이 더 큽니다. 모든 알고리즘에 같은 편향이라 비교에는 영향이 없고, 절대값을 해석할 때만 주의합니다.

### 2.8 추종 오차 (`track_pos_err_mean_m`) — 참고용, 순위에 쓰지 않음

- **계산:** 4번 `pos_err`의 평균
- **단위:** m
- **순위에 쓰지 않는 이유:** 각 알고리즘이 스스로 줄이도록 만들어진 양이라, 순위에 쓰면 알고리즘이 자기 목표에서 이기는 것을 재게 됩니다 (학생 안내서 5-3).

### 2.9 환경 충돌률 (`env_collision_rate`, `env_max_penetration_m`) — 참고용, 순위에 쓰지 않음

- **배경:** 손목 경로에 장애물이 있는 시나리오에서는 사람 손목이 장애물을 피했어도 로봇 팔꿈치·링크가 장애물에 부딪힐 수 있습니다. 알고리즘마다 팔꿈치 자세가 달라 이 지표에서 차이가 날 것으로 봅니다. 멘토: 큰 영향은 없지만 있으면 좋음, 진행 (Q1).
- **계산:** 로봇 몸체와 환경(테이블·장애물) 사이 접촉만 봅니다. 접촉의 두 몸체 중 하나라도 로봇 몸체가 아니면 환경 접촉입니다 (`replay`의 `is_self_contact`가 거짓인 것).
  ```
  env_depth[t] = min( {d : (b1, b2, d) ∈ contacts[t], 환경 접촉}, 기본값 0 )
  env_collision_rate    = mean_t ( env_depth[t] < 0 )
  env_max_penetration_m = −min_t env_depth[t]   (모두 ≥ 0 이면 0)
  ```
- **단위:** 비율, m
- **장면:** 에피소드마다 3번 `obstacles.json`의 테이블 좌표계 박스(테이블·방해물·아크릴 판)를 4번 좌표 변환(`to_robot_point`와 같은 변환)으로 로봇 베이스 좌표로 옮겨 5-1 재생 장면에 넣습니다. 장애물이 없는 에피소드는 테이블만 둡니다.
- 2.3 자기 충돌률은 로봇 몸체끼리의 접촉만 세므로, 환경 접촉이 생겨도 2.3 값은 바뀌지 않습니다.
- **순위에 쓰지 않는 이유:** 알고리즘들이 장애물 위치를 모르고 풀기 때문에, 이 지표는 알고리즘 성능보다 "팔꿈치 자세가 우연히 장애물을 피해 갔는가"를 잽니다. 멘토도 "큰 영향은 없지만 있으면 좋음"이라고 답함. 그래서 추종 오차처럼 표는 따로 두고 순위에는 넣지 않습니다 (2026-11-05 결정).

## 4. 집계 (`summary.md`)

- 에피소드 하나가 케이스 태그를 여러 개 가질 수 있으므로 **태그마다 한 번씩** 세어 집계합니다.
- 지표마다 표 하나. 행 = 케이스, 열 = 알고리즘, 칸 = **"중앙값 (최악값)"**
  - 모든 지표가 낮을수록 좋으므로 최악값 = 최댓값
  - 평균만 쓰지 않는 이유: "가끔 크게 실패하는가"가 평균만큼 중요합니다.
- 칸마다 에피소드 수를 함께 적고, **5개 미만인 칸은 표시**합니다. (멘토에게 물었으나 따로 답이 없어 초안대로 둠, Q5)
- 추종 오차·환경 충돌률 표는 "참고"로 따로 둡니다.

## 5. 이상값 확인 (`worst_episodes.md`)

- 표의 칸마다 가장 나쁜 에피소드 3개를 뽑아 5-1번 나란히 보기 영상으로 봅니다.
- 그 값이 알고리즘의 실제 거동인지, 계산·검출 설정의 오류인지 판단합니다.
- 오류라면 이 정의서를 고치고(9절에 기록) 모든 알고리즘에 다시 적용합니다.

## 6. 계산 코드 검증 (합성 데이터)

실데이터 전에, 정답을 아는 궤적으로 지표 코드가 정답을 내는지 확인합니다. 모두 통과해야 실데이터에 씁니다.

| 지표 | 만드는 법 | 나와야 할 값 |
|---|---|---|
| 한계 위반율 | 100프레임 중 10프레임에서 관절 1을 한계보다 0.1 rad 넘게 | 0.1 |
| 자기 충돌률 | 5-1번이 찾은 자기 충돌 자세를 100프레임 중 20프레임에 넣기 | 0.2 |
| IK 실패율 | 상태 코드 배열을 직접 만들기 | 만든 비율 그대로 |
| 저크 RMS | 관절 하나를 q = A·sin(ωt)로, 주기가 정수 번 들어가게. 30 fps와 60 fps 두 가지로 만들기 | 둘 다 A·ω³ ÷ √2에 가까운 값 (60 fps도 30 Hz로 맞춰 계산되는지 확인) |
| 파지점 거리 | 사람 파지점을 로봇 TCP와 같은 점으로 | 0 |

4번의 합성 궤적 네 종류(직선·원, 뻗기, 한계 근처, 팔꿈치)도 넣어, 4번 담당이 확인한 거동 차이가 지표에서도 보이는지 확인합니다.

## 8. 계산에서 빼는 에피소드

모든 알고리즘에 똑같이 적용합니다. 뺀 에피소드와 이유는 `summary.md`에 목록으로 적습니다.

- `sync/sync.csv`에서 `usable = 0`인 에피소드 (두 영상의 시간을 맞출 수 없음)
- 3번 라벨에 `grasp_frame`이 없거나, 그 프레임의 엄지 끝·검지 끝 3D가 NaN인 에피소드는 **파지점 거리만** 빼고 나머지 지표는 계산 (뺀 수를 `summary.md`에 적음)
- IK 실패나 키포인트 누락이 많다는 이유로는 빼지 않습니다 (그 자체가 비교 지표)
