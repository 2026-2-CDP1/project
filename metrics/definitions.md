# 지표 정의서

> 담당: 신서연 (5-2. 지표 계산)
> 상태: **v0.3 (2026-11-05)** — 지표 구성 개편 (팀 검토 반영). 10절에 남은 항목을 정하고 멘토 확인을 받으면 **고정**하고, 그 뒤로는 결과를 보기 전과 같은 정의만 씁니다.
> 근거: 역할 가이드 「5-2. 지표 계산」 1단계, 학생 안내서 5-1·5-3. 가이드에서 바꾼 것은 7절 표와 9절에 이유를 적음

## 0. 원칙

1. **정의는 결과를 보기 전에 고정합니다.** 결과를 본 뒤 정의를 바꾸면 특정 알고리즘에 유리하게 바꿨다는 의심을 피할 수 없습니다.
2. 정의를 바꿔야 하면 9절 변경 기록에 이유를 적고, **모든 알고리즘·모든 에피소드에 다시 적용**합니다.
3. 모든 지표는 **에피소드 하나 × 알고리즘 하나** 단위로 계산합니다.
4. 모든 지표는 **낮을수록 좋습니다.**
5. **실패를 지우지 않습니다.** IK 실패 프레임, 키포인트 누락 프레임도 그대로 포함해 계산합니다.
6. 같은 에피소드는 모든 알고리즘에서 같은 프레임 구간을 씁니다. 에피소드를 빼는 기준(8절)도 모든 알고리즘에 똑같이 적용합니다.
7. **알고리즘이 스스로 줄이도록 만들어진 값은 순위에 쓰지 않습니다** (학생 안내서 5-3). 순위에 쓰면 알고리즘이 자기 목표에서 이기는 것을 재게 됩니다.
8. 지표는 세 묶음으로 씁니다.
   - **순위:** 대표 알고리즘을 고르는 데 씀
   - **안전 확인:** 모든 알고리즘에서 0이어야 함. 0이 아니면 계산·설정 오류를 먼저 의심
   - **참고:** 표는 만들되 순위에는 안 씀. 원인 분석과 논문 결론(정확도·속도)에 씀

## 1. 입력

| 기호 | 내용 | 출처 |
|---|---|---|

| `status` | (T,) IK 상태 코드. 0 = 성공, 1 = 미수렴, 2 = 해 없음 | 4번 npz |

| `tcp_pos`, `contacts` | 프레임별 TCP 위치(m, 로봇 베이스 좌표), 접촉 목록 | 5-1번 `replay(q)` |
| 로봇 어깨·팔꿈치·손목 | 관절 2·4·6 중심 (`link2`, `link4`, `link6` 원점) | 5-1번 재생 모델 |

## 2. 지표

### 2.1 관절 한계 위반율 (`limit_violation_rate`) — 안전 확인

- **계산:** 어느 한 관절이라도 한계를 `ε = 1e-6 rad` 넘게 벗어난 프레임 수 ÷ 전체 프레임 수
  ```
  viol[t] = any_j ( q[t,j] < lo[j] − ε  or  q[t,j] > hi[j] + ε )
  limit_violation_rate = mean_t viol[t]
  ```
- **단위:** 비율 (0~1)
- **안전 확인으로 둔 이유 (v0.3):** A(DLS)는 계산 뒤에 잘라내고, B(mink)는 한계를 제약으로 풀고, C(EAIK)는 한계 밖 해를 버립니다. 그래서 셋 다 구조상 0이 되어 알고리즘을 구분하지 못합니다. 0이 아니면 그 알고리즘 구현이나 관절 순서가 틀린 것이라 먼저 확인합니다.

### 2.2 관절 한계 근접률 (`limit_proximity_rate`) — 순위

- **계산:** 어느 한 관절이라도 한계에서 **δ = 1°** 안에 있는(넘은 것 포함) 프레임 수 ÷ 전체 프레임 수
  ```
  near[t] = any_j ( q[t,j] < lo[j] + δ  or  q[t,j] > hi[j] − δ )
  limit_proximity_rate = mean_t near[t]
  ```
- **단위:** 비율
- **왜:** 한계에 붙어 있다는 것은 목표를 따라가려다 막혔거나(A가 잘라낸 경우), 여유 없이 버틴 것(B가 제약에 걸린 경우)입니다. 실제 로봇에서는 한계 근처가 위험하고 다음 동작의 여유도 없습니다.
- **가이드의 포화율을 대신하는 이유 (v0.3):** 포화율은 4번 `saturated` 플래그를 알고리즘마다 다른 방식으로 채워야 했습니다. 근접률은 **출력 각도만 보고 모든 알고리즘에 같은 기준**으로 계산하므로 그 문제가 없습니다. A가 잘라낸 프레임(정확히 한계값)도 여기에 잡힙니다.

### 2.3 자기 충돌률 (`self_collision_rate`) — 순위

- **계산:** 로봇 몸체끼리의 접촉 중 거리가 음수(파고듦)인 쌍이 하나라도 있는 프레임 수 ÷ 전체 프레임 수
  ```
  depth[t] = min( {d : (b1, b2, d) ∈ contacts[t], b1·b2 모두 로봇 몸체}, 기본값 0 )
  self_collision_rate = mean_t ( depth[t] < 0 )
  ```
- **단위:** 비율
- **검출 조건:** 제외 쌍은 **2개: `base`–`link1`, `link5`–`link7`** (`replay/collision_exclude.md` 확정, 멘토 Q4).
- **해석 시 주의:** 충돌 형상이 링크마다 구(sphere) 여러 개로 근사돼 있어, 실제 외형보다 넓거나 좁게 잡히는 곳이 있습니다. 모든 알고리즘에 같은 조건이라 비교는 유효하고, 절대값을 해석할 때 이 조건을 함께 적습니다.

### 2.4 최대 침투 깊이 (`max_penetration_m`) — 참고

- **계산:** 모든 프레임에서 가장 깊게 파고든 로봇 자기 접촉의 깊이. 충돌이 없으면 0
  ```
  max_penetration_m = −min_t depth[t]   (모든 depth[t] ≥ 0 이면 0)
  ```
- **단위:** m
- 2.3의 짝입니다. 충돌률이 같을 때 얼마나 심한지 보는 데 씁니다.

### 2.5 IK 실패율 (`ik_failure_rate`) — 순위 / 세부 `ik_not_converged_rate`, `ik_no_solution_rate`

- **계산:**
  ```
  ik_failure_rate       = mean_t ( status[t] ≠ 0 )
  ik_not_converged_rate = mean_t ( status[t] = 1 )
  ik_no_solution_rate   = mean_t ( status[t] = 2 )
  ```
- **단위:** 비율
- 실패 프레임에서 각 알고리즘이 무엇을 내놓는지(직전 자세 유지 등)는 4번 공통 규칙을 따르며, 그 값도 다른 지표 계산에 그대로 포함합니다.
- **해가 없을 때는 알고리즘별 방식을 그대로 씁니다** (멘토, Q11). 특정 알고리즘에만 재탐색이나 보정 규칙을 덧붙이지 않습니다.
- **수렴 기준은 반복 계산하는 알고리즘(A·B)에 똑같이** 적용해야 합니다 (위치 오차 ε_p, 방향 오차 ε_r, 반복 횟수 N). 기준 하나로 미수렴 비율이 크게 바뀌므로(4번 시험: B 95% 오차 2 mm인데 미수렴 80%), 4번이 결과를 보기 전에 `config.json`에 고정합니다 (10절).

### 2.6 저크 RMS (`jerk_rms`) — 순위

- **계산:** **30 Hz로 맞춘 궤적**에서 관절 각도의 3차 차분 ÷ Δt³의 제곱평균제곱근. 7개 관절과 모든 프레임을 한꺼번에 평균합니다.
  ```
  # 30 Hz로 맞추기 (보간·스무딩 없이 프레임만 고름)
  k  = round( (1/30) / median(diff(ts)) )        # 60 fps 에피소드 → 2, 30 fps 에피소드 → 1
  q  = q[::k],  ts = ts[::k]                     # 첫 프레임부터 k칸마다
  Δt = median(diff(ts))                          # 실제 간격 (≈ 1/30 s)
  jerk[t,j] = ( q[t+3,j] − 3·q[t+2,j] + 3·q[t+1,j] − q[t,j] ) / Δt³      (t = 0 … T−4)
  jerk_rms  = sqrt( mean_{t,j} jerk[t,j]² )
  ```
- **단위:** rad/s³
- **30 Hz로 맞추는 이유:** 기준 시간축 exo_front가 본 촬영에서 **T1·T3 59.97 fps, T2 30.00 fps**입니다 (`sync/protocol.md`). 저크는 Δt³로 나누므로 fps에 크게 좌우됩니다 (같은 키포인트 노이즈가 60 fps에서 약 8배). 모든 에피소드를 30 Hz로 맞춥니다 (2026-11-05 결정).
- 고르는 것은 저크·속도(2.7) 계산에만 씁니다. 다른 지표는 모든 프레임으로 계산합니다.
- **한계:** 60 fps 에피소드에서 버려진 프레임에만 생긴 짧은 튐은 저크에 안 잡힙니다. 그런 튐은 IK 실패율 등 모든 프레임으로 계산하는 지표에는 남습니다.
- `Δt`가 1/30 s와 0.1% 넘게 다른 에피소드는 `summary.md`에 표시합니다.
- IK 실패 프레임도 포함합니다. 실패 때문에 궤적이 튀는 것도 알고리즘의 특성입니다.

### 2.7 관절 속도 한계 초과율 (`velocity_limit_exceed_rate`) — 순위 (v0.3 추가)

- **계산:** 2.6과 같이 30 Hz로 맞춘 궤적에서, 이웃 프레임 사이 각속도가 한 관절이라도 속도 한계를 넘은 구간의 비율
  ```
  v[t,j] = | q[t+1,j] − q[t,j] | / Δt                  (30 Hz로 맞춘 q, t = 0 … T−2)
  velocity_limit_exceed_rate = mean_t any_j ( v[t,j] > vmax[j] )
  ```
- **단위:** 비율
- **왜:** 실제 로봇이 그 속도로 따라갈 수 있는 궤적인지를 직접 보여 줍니다. 해가 바뀌며 생기는 **몇 번의 점프**(예: 닫힌 해 C의 해 전환)는 저크 RMS에서는 평균에 묻힐 수 있지만, 이 지표에서는 한 번만 넘어도 셉니다.
- **해석 시 주의:** 사람 시연 자체가 빠르면(케이스 "빠른 동작") 모든 알고리즘이 넘을 수 있습니다. 비교는 같은 에피소드 안에서 알고리즘끼리 합니다.

### 2.8 팔 회전각 차이 (`arm_angle_diff_rad`) — 조건부 순위 (v0.3 추가)

- **무엇:** 7자유도 팔은 손목 자세를 정해도 팔꿈치가 어깨–손목 축 둘레로 돌 수 있습니다. 그 각도(팔 회전각, SEW 각)가 사람과 로봇에서 얼마나 다른지 잽니다. "로봇 팔이 사람처럼 움직였나"를 보는 지표입니다.
- **계산:** 사람 어깨·팔꿈치·손목(`kp`의 `shoulder`, `elbow`, `wrist`)을 `to_robot_point`로 로봇 좌표로 옮기고, 로봇 어깨·팔꿈치·손목(관절 2·4·6 중심)과 **같은 방식**으로 각을 구합니다.
  ```
  a = (W − S) / |W − S|                       어깨→손목 축
  e = 팔꿈치 (E − S)를 a에 수직인 평면에 투영
  r = 아래 방향 (0, 0, −1)을 a에 수직인 평면에 투영
  ψ = atan2( a · (r × e),  r · e )             팔 회전각 (rad)
  arm_angle_diff_rad = median_t | wrap(ψ_로봇[t] − ψ_사람[t]) |      wrap: −π~π
  ```
- **단위:** rad (표에는 °로도 적음)
- 사람 키포인트가 NaN이거나, 어깨–손목 축이 거의 수직(|a·아래| > 0.99)이라 각을 정할 수 없는 프레임은 뺍니다. 쓴 프레임 비율을 `episode_info.csv`에 적습니다.
- `to_robot_point`는 평행 이동·축척·회전이라 각도를 바꾸지 않습니다. 그래서 사람 각을 로봇 좌표에서 재도 같습니다.
- **조건부 순위인 이유:** 알고리즘이 사람 팔꿈치를 입력으로 받아 이 값을 줄이도록 풀면, 이 값은 추종 오차처럼 "자기 목표"가 되어 순위에 쓸 수 없습니다 (원칙 7).
  - **모든 알고리즘이 손목만 받으면:** 팔꿈치는 각 알고리즘이 정한 결과이므로 → **순위**
  - **팔꿈치 정보를 입력으로 주면 (A·B·C 모두 같게):** → **참고**
  - 어느 쪽인지는 4번·팀이 정하고(10절), 결과를 보기 전에 여기 적습니다.

### 2.9 추종 오차 (`track_pos_err_mean_m`, `track_rot_err_mean_rad`) — 참고

- **계산:** 4번 `pos_err`의 평균 (m), `rot_err`의 평균 (rad)
- **순위에 쓰지 않는 이유:** 각 알고리즘이 스스로 줄이도록 만들어진 양입니다 (원칙 7).
- **논문에서:** 알고리즘별 "정확도"로 보고합니다. 2.5 IK 실패율, 2.8 팔 회전각 차이와 같이 봅니다.

### 2.10 파지점 거리 (`grasp_dist_m`) — 참고 (v0.3에서 순위 → 참고)

- **계산:** 파지 프레임 `g`에서 로봇 TCP와 사람 파지점(로봇 좌표로 옮긴 것) 사이 거리
  ```
  p_human = to_robot_point( (kp[g, thumb_tip] + kp[g, index_tip]) / 2 )
  grasp_dist_m = ‖ tcp_pos[g] − p_human ‖
  g = grasp_frame − exo_start_frame
  ```
- **단위:** m
- **사람 파지점:** 엄지 끝·검지 끝의 중점, exo 3대 삼각측량 (멘토 Q2). **첫 파지만** (`grasp_frame` 하나, 멘토 Q3).
- `kp[g]`의 엄지 끝·검지 끝 중 하나라도 NaN이면 NaN으로 두고 이 지표에서만 뺍니다 (8절).
- **참고로 내린 이유 (v0.3):** 로봇 목표는 사람 손목에서 만들고 TCP는 플랜지입니다. 그래서
  ```
  grasp_dist = (파지 프레임의 손목 추종 오차) + (손목–손가락 끝 편향, 모든 알고리즘에 같음)
  ```
  이 됩니다. 알고리즘 사이 차이는 사실상 한 프레임의 추종 오차뿐이라, 추종 오차를 순위에 안 쓰는 원칙(원칙 7)과 맞춰 참고로 둡니다. 편향 때문에 절대값(수 cm)도 작게 나올 수 없습니다.
- `g` 프레임이 실제로 잡는 순간인지는 파일럿 에피소드의 나란히 보기 영상으로 확인합니다.

### 2.11 환경 충돌률 (`env_collision_rate`, `env_max_penetration_m`) — 참고

- **계산:** 로봇 몸체와 환경(테이블·장애물) 사이 접촉만 봅니다 (`replay`의 `is_self_contact`가 거짓인 것).
  ```
  env_depth[t] = min( {d : (b1, b2, d) ∈ contacts[t], 환경 접촉}, 기본값 0 )
  env_collision_rate    = mean_t ( env_depth[t] < 0 )
  env_max_penetration_m = −min_t env_depth[t]   (모두 ≥ 0 이면 0)
  ```
- **단위:** 비율, m
- **장면:** 에피소드마다 3번 `obstacles.json`의 상자와 테이블을 `to_robot_point`와 같은 변환으로 옮겨 넣습니다 (`replay/scene.md`). 장애물이 없는 에피소드는 테이블만 둡니다. 장면이 없으면 0이 아니라 NaN입니다.
- **참고로 두는 이유:** 알고리즘들이 테이블·장애물 위치를 모르고 풀기 때문에 "팔꿈치 자세가 우연히 피해 갔는가"를 잽니다. 또 테이블 면의 높이는 축척 변환으로 정해져 실제 설치 높이가 아닙니다. 멘토: 큰 영향은 없지만 있으면 좋음 (Q1, 2026-11-05 참고용으로 결정).
- 팔꿈치가 테이블 아래로 파고드는 경우를 보여 주므로 2.8과 같이 원인 분석에 씁니다.

### 2.12 최소 조작성 (`min_manipulability`) — 참고 (v0.3 추가)

- **계산:** 프레임마다 TCP 야코비안(6×7, 위치 3 + 방향 3)으로 조작성 `w = sqrt(det(J·Jᵀ))`를 구하고, 에피소드에서 가장 작은 값
- **단위:** 없음 (위치·방향 단위가 섞여 절대값보다 비교에 씀)
- **왜:** 0에 가까우면 특이 자세(팔을 쭉 편 자세 등)입니다. 특이 자세 근처에서 DLS는 감쇠로 안정적으로 지나고 닫힌 해는 불안정해지는 차이를 **설명**하는 데 씁니다. 낮을수록 나쁜 방향이 아니라 "위험한 자세에 가까웠다"는 뜻이라 순위에는 안 씁니다.

### 2.13 계산 시간 (`compute_ms_median`) — 참고 (v0.3 추가)

- **계산:** 4번 `time_ms`(프레임당 계산 시간)의 중앙값. 95% 값은 `episode_info.csv`에 따로 적습니다.
- **단위:** ms
- **조건:** 모든 알고리즘을 **같은 서버 노드, 같은 설정**에서 잰 값이어야 비교할 수 있습니다 (4번이 노드 이름을 `config.json`에 적음).
- **논문에서:** 알고리즘별 "속도"로 보고하고 "케이스별 알고리즘 선택 지침"의 실용 정보로 씁니다.

## 4. 집계 (`summary.md`)

- 에피소드 하나가 케이스 태그를 여러 개 가질 수 있으므로 **태그마다 한 번씩** 세어 집계합니다.
- 지표마다 표 하나. 행 = 케이스, 열 = 알고리즘, 칸 = **"중앙값 (최악값)"**
  - 모든 지표가 낮을수록 좋으므로 최악값 = 최댓값 (최소 조작성만 최솟값)
  - 평균만 쓰지 않는 이유: "가끔 크게 실패하는가"가 평균만큼 중요합니다.
- 칸마다 에피소드 수를 함께 적고, **5개 미만인 칸은 표시**합니다. (멘토 Q5 답 없음, 초안 유지)
- 순위 지표 표를 먼저, 안전 확인(0이 아닌 칸만), 참고 지표 표를 따로 둡니다.
- **논문 결론용 요약:** 알고리즘마다 정확도(2.5·2.8·2.9), 부드러움(2.6·2.7), 안전(2.2·2.3), 속도(2.13)를 한 줄로 모읍니다.

- 순위 지표 표의 칸마다 가장 나쁜 에피소드 3개를 뽑아 5-1번 나란히 보기 영상으로 봅니다.
- 그 값이 알고리즘의 실제 거동인지, 계산·검출 설정의 오류인지 판단합니다.
- 오류라면 이 정의서를 고치고(9절에 기록) 모든 알고리즘에 다시 적용합니다.
