# 지표 정의서

> 담당: 신서연 (5-2. 지표 계산)
> 상태: **초안 v0.1 (2026-10-16)** — 멘토 확인 전. 확인 후 **고정**하고, 그 뒤로는 결과를 보기 전과 같은 정의만 씁니다.
> 근거: 역할 가이드 「5-2. 지표 계산」 1단계, 학생 안내서 5-1·5-3

---

## 0. 원칙

1. **정의는 결과를 보기 전에 고정합니다.** 결과를 본 뒤 정의를 바꾸면 특정 알고리즘에 유리하게 바꿨다는 의심을 피할 수 없습니다.
2. 정의를 바꿔야 하면 9절 변경 기록에 이유를 적고, **모든 알고리즘·모든 에피소드에 다시 적용**합니다.
3. 모든 지표는 **에피소드 하나 × 알고리즘 하나** 단위로 계산합니다.
4. 모든 지표는 **낮을수록 좋습니다.**
5. **실패를 지우지 않습니다.** IK 실패 프레임, 키포인트 누락 프레임도 그대로 포함해 계산합니다.
6. 같은 에피소드는 모든 알고리즘에서 같은 프레임 구간을 씁니다. 에피소드를 빼는 기준(8절)도 모든 알고리즘에 똑같이 적용합니다.

## 1. 입력

| 기호 | 내용 | 출처 |
|---|---|---|
| `q` | (T, 7) 팔 관절 각도, rad | 4번 `retarget/<알고리즘>/<에피소드ID>.npz` |
| `saturated` | (T, 7) 관절이 한계에 걸려 값이 잘렸는지 (bool) | 4번 npz |
| `status` | (T,) IK 상태 코드. 0 = 성공, 1 = 미수렴, 2 = 해 없음 | 4번 npz |
| `gripper` | (T,) 그리퍼 벌림 0~1 | 4번 npz |
| `pos_err` | (T,) 목표와 TCP의 위치 오차, m (4번 `tcp_error`) | 4번 npz |
| `lo`, `hi` | (7,) 관절 하한·상한, rad | 1번 `robot/joint_limits.csv` (`lower_rad`, `upper_rad`) |
| `tcp_pos`, `contacts` | 프레임별 TCP 위치(m, 로봇 베이스 좌표), 접촉 목록 | 5-1번 `replay(q, gripper)` |
| `Δt` | 프레임 간격, s | exo 영상의 `data.jsonl` 프레임 시각 |
| `g` | 파지 프레임의 배열 인덱스 | 3번 라벨 (2.7절) |
| `kp` | (T, K, 3) 테이블 좌표계 키포인트, m | 3번 키포인트 |

- 배열 길이 `T`는 에피소드 구간(3번 라벨의 시작~끝)의 프레임 수입니다. 4번 배열과 3번 키포인트는 같은 exo 시간축입니다.
- 관절 한계는 1번 `robot/joint_limits.csv`의 `lower_rad`, `upper_rad`를 씁니다 (iiwa14: joint1·3·5 ±2.96706, joint2·4·6 ±2.09440, joint7 ±3.05433 rad).

## 2. 지표

### 2.1 관절 한계 위반율 (`limit_violation_rate`)

- **계산:** 어느 한 관절이라도 한계를 `ε = 1e-6 rad` 넘게 벗어난 프레임 수 ÷ 전체 프레임 수
  ```
  viol[t] = any_j ( q[t,j] < lo[j] − ε  or  q[t,j] > hi[j] + ε )
  limit_violation_rate = mean_t viol[t]
  ```
- **단위:** 비율 (0~1)
- `ε`는 수치 오차를 빼기 위한 값입니다.

### 2.2 관절 한계 포화율 (`limit_saturation_rate`) — 보조

- **계산:** 어느 한 관절이라도 `saturated`가 참인 프레임 수 ÷ 전체 프레임 수
- **단위:** 비율
- **따로 두는 이유:** 알고리즘 A(DLS)는 한계 밖 값을 계산 뒤에 잘라내므로 최종 출력의 한계 위반율이 항상 0입니다. 대신 목표를 못 따라간 흔적이 포화율에 남습니다. 이 지표가 없으면 A가 한계 처리에서 부당하게 좋아 보입니다.
- 한계를 제약으로 푸는 알고리즘(B mink)은 잘라내는 단계가 없으므로 4번이 `saturated`를 어떻게 채우는지 확인이 필요합니다 (10절).

### 2.3 자기 충돌률 (`self_collision_rate`)

- **계산:** 로봇 몸체끼리의 접촉 중 거리가 음수(파고듦)인 쌍이 하나라도 있는 프레임 수 ÷ 전체 프레임 수
  ```
  depth[t] = min( {d : (b1, b2, d) ∈ contacts[t], b1·b2 모두 로봇 몸체}, 기본값 0 )
  self_collision_rate = mean_t ( depth[t] < 0 )
  ```
- **단위:** 비율
- **검출 조건:** 5-1번 `replay/collision_exclude.md`에서 확정한 제외 쌍을 뺀 상태로 계산합니다. 제외 목록은 이 지표 값을 바꾸므로 **결과를 보기 전에 확정**합니다.
  - 현재 `robot/robot.xml`(Menagerie 원본)에는 제외 쌍 7개가 들어 있습니다: base–link1, base–link2, base–link3, link1–link3, link3–link5, link4–link7, link5–link7. 이 목록을 그대로 쓸지 5-1에서 검토합니다.
- **해석 시 주의:** MuJoCo는 메시 충돌 형상을 볼록 껍질로 계산해 오목한 부위의 충돌이 실제보다 넓게 잡힐 수 있습니다. 모든 알고리즘에 같은 조건이라 비교는 유효하고, 절대값을 해석할 때 이 조건을 함께 적습니다.

### 2.4 최대 침투 깊이 (`max_penetration_m`)

- **계산:** 모든 프레임에서 가장 깊게 파고든 로봇 자기 접촉의 깊이. 충돌이 없으면 0
  ```
  max_penetration_m = −min_t depth[t]   (모든 depth[t] ≥ 0 이면 0)
  ```
- **단위:** m

### 2.5 IK 실패율 (`ik_failure_rate`, `ik_not_converged_rate`, `ik_no_solution_rate`)

- **계산:**
  ```
  ik_failure_rate       = mean_t ( status[t] ≠ 0 )
  ik_not_converged_rate = mean_t ( status[t] = 1 )
  ik_no_solution_rate   = mean_t ( status[t] = 2 )
  ```
- **단위:** 비율
- 실패 프레임에서 각 알고리즘이 무엇을 내놓는지(직전 자세 유지 등)는 4번 공통 규칙을 따르며, 그 값도 다른 지표 계산에 그대로 포함합니다.

### 2.6 저크 RMS (`jerk_rms`)

- **계산:** 관절 각도의 3차 차분 ÷ Δt³의 제곱평균제곱근. 7개 관절과 모든 프레임을 한꺼번에 평균합니다.
  ```
  jerk[t,j] = ( q[t+3,j] − 3·q[t+2,j] + 3·q[t+1,j] − q[t,j] ) / Δt³      (t = 0 … T−4)
  jerk_rms  = sqrt( mean_{t,j} jerk[t,j]² )
  ```
- **단위:** rad/s³
- **Δt:** exo 기기(iPhone 18 Pro)의 프레임 간격. 시험 촬영에서 30.00 fps로 일정했으므로 `Δt = 1/30 s`로 고정하고, 에피소드마다 `data.jsonl` 프레임 간격의 중앙값이 1/30 s와 0.1% 넘게 다르면 표시합니다.
- **모든 에피소드가 같은 fps여야 합니다.** 저크는 Δt³로 나누므로 fps에 크게 좌우됩니다.
- IK 실패 프레임도 포함합니다. 실패 때문에 궤적이 튀는 것도 알고리즘의 특성입니다.

### 2.7 파지점 거리 (`grasp_dist_m`)

- **계산:** 파지 프레임 `g`에서 로봇 TCP와 사람 파지점(로봇 좌표로 옮긴 것) 사이 거리
  ```
  p_human = to_robot_point( (kp[g, thumb_tip] + kp[g, index_tip]) / 2 )
  grasp_dist_m = ‖ tcp_pos[g] − p_human ‖
  ```
- **단위:** m
- **파지 프레임 인덱스:** 3번 라벨의 프레임 번호는 exo 영상 전체 기준, 4번 배열은 에피소드 구간만 담습니다.
  ```
  g = (라벨의 파지 프레임) − (에피소드 시작 프레임)
  ```
  하나만 틀려도 이 지표 전체가 틀리므로, 파일럿 에피소드에서 5-1번 나란히 보기 영상의 `g` 프레임이 실제로 잡는 순간인지 확인합니다.
- **파지가 여러 번인 에피소드:** 첫 번째 파지 프레임만 씁니다. (10절 확인 필요)
- **TCP:** 그리퍼 두 손가락 끝의 중간점 (1번이 정의하는 `tcp` site). 그리퍼가 붙기 전 시험 계산은 플랜지(`attachment_site`)로 하되, 그 값은 비교에 쓰지 않습니다.
- **해석 시 주의:** 로봇 목표는 사람 손목에서 만들고 파지점은 손가락 쪽에 있으므로, 완벽하게 따라가도 0이 되지 않습니다. 모든 알고리즘에 같은 편향이라 비교에는 영향이 없고, 절대값을 해석할 때만 주의합니다.

### 2.8 추종 오차 (`track_pos_err_mean_m`) — 참고용, 순위에 쓰지 않음

- **계산:** 4번 `pos_err`의 평균
- **단위:** m
- **순위에 쓰지 않는 이유:** 각 알고리즘이 스스로 줄이도록 만들어진 양이라, 순위에 쓰면 알고리즘이 자기 목표에서 이기는 것을 재게 됩니다 (학생 안내서 5-3).

### 2.9 환경 충돌률 (`env_collision_rate`) — **제안, 멘토 확인 필요**

- **배경:** 멘토 피드백에 따라 손목 경로에 장애물이 있는 시나리오를 추가하면, 사람 손목은 장애물을 피했어도 로봇 팔꿈치·링크가 장애물에 부딪힐 수 있습니다. 알고리즘마다 팔꿈치 자세가 달라 이 지표에서 차이가 날 것으로 봅니다.
- **계산:** 로봇 몸체와 환경(테이블·장애물) 사이 접촉 중 거리가 음수인 쌍이 하나라도 있는 프레임 수 ÷ 전체 프레임 수. 최대 침투 깊이도 같은 방식으로 따로 기록합니다.
- **단위:** 비율
- **필요한 것:** 배치마다 테이블·장애물의 크기와 위치를 테이블 좌표계로 재서 5-1 재생 장면에 넣어야 합니다 (2번·5-1).
- 장애물이 없는 배치에서는 테이블만 환경으로 둡니다.

## 4. 집계 (`summary.md`)

- 에피소드 하나가 케이스 태그를 여러 개 가질 수 있으므로 **태그마다 한 번씩** 세어 집계합니다.
- 지표마다 표 하나. 행 = 케이스, 열 = 알고리즘, 칸 = **"중앙값 (최악값)"**
  - 모든 지표가 낮을수록 좋으므로 최악값 = 최댓값
  - 평균만 쓰지 않는 이유: "가끔 크게 실패하는가"가 평균만큼 중요합니다.
- 칸마다 에피소드 수를 함께 적고, **5개 미만인 칸은 표시**합니다.
- 추종 오차 표는 "참고"로 따로 둡니다.

## 5. 이상값 확인 (`worst_episodes.md`)

- 표의 칸마다 가장 나쁜 에피소드 3개를 뽑아 5-1번 나란히 보기 영상으로 봅니다.
- 그 값이 알고리즘의 실제 거동인지, 계산·검출 설정의 오류인지 판단합니다.
- 오류라면 이 정의서를 고치고(9절에 기록) 모든 알고리즘에 다시 적용합니다.

## 6. 계산 코드 검증 (합성 데이터)

실데이터 전에, 정답을 아는 궤적으로 지표 코드가 정답을 내는지 확인합니다. 모두 통과해야 실데이터에 씁니다.

| 지표 | 만드는 법 | 나와야 할 값 |
|---|---|---|
| 한계 위반율 | 100프레임 중 10프레임에서 관절 1을 한계보다 0.1 rad 넘게 | 0.1 |
| 자기 충돌률 | 5-1번이 찾은 자기 충돌 자세를 100프레임 중 20프레임에 넣기 | 0.2 |
| IK 실패율 | 상태 코드 배열을 직접 만들기 | 만든 비율 그대로 |
| 저크 RMS | 관절 하나를 q = A·sin(ωt)로, 주기가 정수 번 들어가게 | A·ω³ ÷ √2에 가까운 값 |
| 파지점 거리 | 사람 파지점을 로봇 TCP와 같은 점으로 | 0 |

4번의 합성 궤적 네 종류(직선·원, 뻗기, 한계 근처, 팔꿈치)도 넣어, 4번 담당이 확인한 거동 차이가 지표에서도 보이는지 확인합니다.

## 8. 계산에서 빼는 에피소드

모든 알고리즘에 똑같이 적용합니다. 뺀 에피소드와 이유는 `summary.md`에 목록으로 적습니다.

- `sync/sync.csv`에서 `usable = 0`인 에피소드 (두 영상의 시간을 맞출 수 없음)

- IK 실패나 키포인트 누락이 많다는 이유로는 빼지 않습니다 (그 자체가 비교 지표)

## 10. 멘토·팀 확인이 필요한 것 (고정 전에 해결)

| 항목 | 질문 | 대상 |
|---|---|---|
| 환경 충돌률 (2.9) | 지표로 추가해도 되는지, 순위에 쓸지 | 멘토 |
| 파지점 (2.7) | exo 1 m 거리에서 손가락 끝 깊이가 부정확함(손가락 끝 약 3픽셀, 시험 촬영 10/13). 3번이 손가락 끝 3D를 어떻게 구할지에 따라 `p_human`의 정확도가 달라짐 → 정의를 바꿀지(예: 손등 기준점) 결정 | 멘토, 3번 |
