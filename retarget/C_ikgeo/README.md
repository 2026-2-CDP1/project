# 알고리즘 C: 닫힌 해 IK (SEW 각) — 프로토타입

> **4번(리타게팅) 담당 확인 필요.** 1번 담당이 "iiwa14에서 SEW 방식이 파이썬으로 풀리는가"를 확인하려고 만든 프로토타입이다.
> 알고리즘 C의 기본 방식은 SEW 각으로 가정한다. 4번 담당이 검토해서 그대로 쓰거나 고치거나 바꾼다.

## 왜 SEW 각인가

- 역할 가이드 1번의 IK-Geo 안내: "7자유도용 SEW 각 방식은 stereo-sew 저장소에 있다." `PROJECT_CONTEXT.md` 알고리즘 표도 같다.
- 관절 3을 고정하는 방식(`ik-geo` 파이썬 패키지, `robot/check_ikgeo.py`)은 7자유도의 팔꿈치 여유를 버린다. 그러면 팔꿈치 거동 비교에서 C만 불리해진다.
- SEW 각 ψ 하나로 팔꿈치 위치를 직접 지정한다. 영상에서 뽑은 사람 어깨·팔꿈치·손목으로 ψ를 계산해 그대로 넣을 수 있다.

## 파일

| 파일 | 내용 |
|---|---|
| `sew_ik.py` | `IiwaSEW`: iiwa14 SEW IK. 의존성 numpy. 치수는 `IiwaSEW.from_mujoco(model)`으로 `robot/robot.xml`에서 읽는다 |
| `check_sew_ik.py` | 왕복 검사 (무작위 관절각 → FK → SEW IK → FK) |

```python
ik = IiwaSEW.from_mujoco(mujoco.MjModel.from_xml_path("robot/robot.xml"))
psi = ik.psi_from_points(W, E)        # 손목 W, 팔꿈치 E (로봇 베이스 좌표)
sols = ik.ik(R07, p07, psi)           # link7 목표 회전(3x3)·위치 → 관절각 해 8개
```

## 방식

- stereo-sew(MATLAB, https://github.com/rpiRobotics/stereo-sew)의 KUKA iiwa 14 R820 경우를 파이썬으로 옮겼다. 코드를 그대로 옮긴 것이 아니라 같은 기하로 다시 유도했다.
- 영 자세에서 관절 축은 z, y, z, -y, z, y, z이고, 어깨·팔꿈치·손목·플랜지가 z축 위에 있다.
  `R_07 = Rz(q1) Ry(q2) Rz(q3) Ry(-q4) Rz(q5) Ry(q6) Rz(q7)`
- 풀이 순서:
  1. 손목 W = 목표 위치 − 0.081 × (목표 z축)
  2. 어깨→손목 거리로 팔꿈치가 놓일 원을 구하고, ψ로 원 위의 팔꿈치 위치 E를 정한다
  3. 위팔 방향으로 q1·q2(2해), 아래팔 방향으로 q3·q4(2해)
  4. 남은 회전을 ZYZ로 분해해 q5·q6·q7(2해)
- ψ 정의는 conventional SEW다. 기준 벡터 r(기본값 z축)과 어깨→손목이 이루는 평면을 ψ = 0으로 둔다.

## 검사 결과 (2026-10-16, 무작위 자세 1000개)

- 풀이 실패 0, 자세당 해 8개 (관절 한계 안 평균 7.3개, 최소 2개)
- 해를 FK에 다시 넣었을 때 최대 오차 9.3e-12, SEW 각 오차 2.8e-13 rad, 원래 관절각이 항상 해에 포함됨

## 남은 일 (4번 담당)

1. **기준 벡터 특이점**: 어깨→손목이 기준 벡터 r과 나란하면(기본값이면 팔을 위로 뻗을 때) ψ가 정의되지 않는다. 시험 중 근접도가 0.028까지 내려간 자세가 있었다. stereo-sew의 stereographic SEW로 바꿀지, r을 작업 공간 밖 방향으로 둘지 정한다.
2. **일직선 특이 자세**: q2·q4·q6가 0에 가까우면 0에 가까운 값으로 나누게 된다. 예외 처리가 필요하다.
3. **해 고르기**: 8개 중 무엇을 쓸지(관절 한계 안, 직전 프레임과 가장 가까운 해 등) 정한다.
4. **사람 ψ 계산**: 사람 팔의 ψ도 같은 r과 같은 공식(`psi_from_points`)으로 계산해야 한다. 좌표계는 로봇 베이스 기준이다.
5. **TCP**: 지금은 link7(플랜지 안쪽 원점) 기준이다. 그리퍼와 TCP를 붙인 뒤 손목-TCP 거리로 바꿔야 한다.
