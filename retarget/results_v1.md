## 1. 성공률

| | A (DLS) | B (mink) | C (EAIK) |
|---|---|---|---|
| 전체 목표 프레임 기준 | 61.2% | 70.4% | 72.0% |
| **할 수 있는 목표만** | **83.4%** | **95.7%** | **100%** |
| 에피소드 판정 O / △ / X | 53 / 98 / 73 | 76 / 110 / 38 | 82 / 111 / 31 |

- O = 에피소드 성공률 90% 이상, △ = 50~90%, X = 50% 미만.
- **할 수 있는 목표** = C가 관절 한계 안에서 정확한 해를 찾은 프레임. C는 3번 관절 격자 전체에서 해를 모두 구하므로, C가 못 찾으면 iiwa가 어떤 자세로도 만들 수 없는 목표다 (1° 격자 근사).
- 전체 기준 성공률은 세 알고리즘 모두 아래 "할 수 없는 목표"에 묶여 72%를 넘지 못한다. 알고리즘 차이는 "할 수 있는 목표만" 줄로 본다.

## 2. 할 수 없는 목표 28.5%

목표 프레임 36,484개 중 10,381개 (28.5%). 원인 (로봇 어깨 → 손목 중심 거리로 추정):

| 원인 | 비율 | 뜻 |
|---|---|---|
| 0.82 m 초과 | 55% | 팔을 다 펴도 안 닿음 (먼 곳 배치) |
| 0.41 m 미만 | 43% | 팔꿈치를 다 접어도 너무 가까움 (4번 관절 한계 ±120°, 몸 앞 동작·시작/끝 자세) |
| 거리는 되지만 해 없음 | 2% | 손목 방향·관절 한계 |

- 먼 곳 배치(T1 먼 곳 위에서·옆에서 접근, 컵 앞 장애물)는 목표의 73~79%가 할 수 없는 목표.
- 사람 동작 범위(먼 곳 ↔ 몸 바로 앞)가 iiwa 범위(0.41~0.82 m)보다 넓어서, 축척을 키우거나 줄이면 한쪽이 줄고 다른 쪽이 는다 (아래 5절). 줄이려면 로봇 자리·높이를 바꿔야 함 → 멘토 확인.

## 3. A 실패 진단 (`check_a_fail.py`)

할 수 있는 목표 26,103프레임 중 A 실패 4,335 (16.6%):

| 확인 | 결과 |
|---|---|
| 실패 중 관절이 한계에 붙어 있는 프레임 | **100%** (q6 2,822 · q2 2,572 · q5 2,393 · q1 1,690 · q7 1,696 · q3 988 · q4 637) |
| 같은 프레임에서 B 성공 | 93.9% |
| 그때 A·B 자세가 다른 갈래 (q2·q4·q6 부호가 다름) | 92.0% |
| 1초(30프레임) 이상 이어진 실패 구간이 차지하는 비율 | 76.6% (최장 206프레임) |

→ A는 관절 한계를 반복 끝에서 **잘라내기(clip)** 때문에, 한계에 걸린 관절이 못 간 몫을 나머지 관절이 모른 채 그 자리에 머문다. B는 같은 한계를 QP 제약으로 처리해 나머지 관절이 보정한다. 리허설에서 재시작·반복 500회·팔꿈치 끄기가 효과 없던 것과 같은 원인. 수정(표준 DLS 한계 처리, 한계에 걸린 관절을 묶고 나머지로 다시 풀기)은 별도 PR에서 시험.

## 4. 참고 지표

| | A | B | C |
|---|---|---|---|
| 팔 회전각 차이 (에피소드별 중앙값의 중앙값) | 95° | 82° | 26° |
| IK 시간 ms/프레임 중앙 (95%) | 8.7 (11.9) | 45.3 (46.7) | 38.0 (40.6) |

- 팔 회전각 차이는 5-2에서 참고 지표. A·B는 팔꿈치를 입력으로 받지만 손목 우선이라 사람 팔꿈치와 크게 다르다 (T1_E004 시험의 26~32°보다 훨씬 큼 → 원인 확인 필요, A는 3절 갇힘과 관련 가능).
- 실시간 기준 30 Hz = 33.3 ms. A만 안에 들어옴. B·C는 단일 스레드 기준 초과 (C는 3번 관절 341개 × 해 8개를 매 프레임 계산).
- 방향이 없어 직전 방향을 유지한 프레임(`target_orient_held`)이 있는 에피소드 45개 (사람이 직접 찍은 12개보다 많음 → 3번에 이유 확인).

## 5. 축척: 중앙값 대신 평균 (회의 결과 확인, `v1_mean`)

사람 팔 길이를 224개의 평균(0.5693 m, k = 1.4405, 중앙값보다 −0.8%)으로 바꿔 A·B·C 전체를 다시 실행.

| | v1 (중앙값) | 평균 | 차이 |
|---|---|---|---|
| 할 수 없는 목표 | 28.5% | 28.4% | 안 닿음 55 → 54%, 너무 가까움 43 → 44% |
| 성공률 A / B / C (전체) | 61.2 / 70.4 / 72.0 | 60.5 / 70.4 / 72.1 | |
| 할 수 있는 목표만 A / B / C | 83.4 / 95.7 / 100 | 82.4 / 95.6 / 100 | |
| 판정 A O/△/X | 53 / 98 / 73 | 50 / 101 / 73 | |

→ 차이 1%p 이내. 팔 길이 분포가 좁아(0.535~0.655 m) 평균 ≈ 중앙값. **결론이 축척 통계 선택에 좌우되지 않음** → v1.1(중앙값, 이상값에 강함) 유지. B·C는 그대로이고 A만 흔들림 = 3절 갇힘이 입력에 민감함.

## 파일 (`results/v1/`)

| 파일 | 내용 | 만든 스크립트 |
|---|---|---|
| `summary_<알고리즘>.csv` | 에피소드 × 알고리즘: 손목 오차 95%·최대, 1 cm 초과 수, 팔 회전각, 시간, 빈 값 처리 수 | `run_all.py` |
| `run_info_<작업번호>.json` | 노드, 설정 전체, 축척 k와 에피소드별 팔 길이, 패키지 버전, git 커밋 | `run_all.py` |
| `success_by_episode.csv` | 에피소드 × 알고리즘 성공률과 실패 원인 (위치 / 방향만 / 한계 밖) | `check_success.py` |
| `success_table.csv` | 에피소드 한 줄에 A·B·C 성공률과 O/△/X (엑셀용, UTF-8 BOM) | `episode_table.py` |
| `feasible_by_episode.csv` | 에피소드별 할 수 없는 목표 수, 할 수 있는 목표에서 A·B·C 성공률 | `check_feasible.py` |

다시 만들기 (서버, `source ~/use_robot.sh` 후):

```bash
O=~/out/hyojeong/retarget/v1
python retarget/check_success.py --out $O && python retarget/episode_table.py --out $O --quiet
python retarget/check_feasible.py --out $O && python retarget/check_a_fail.py --out $O
python retarget/export_frames.py --out $O --episodes ~/out/seohyeon/episodes_v1   # 프레임별 성공·실패 (frames.json)
```
