설정에서 A `limits`만 바꿈. clamp = 한계에 걸릴 관절을 한계까지 보내 묶고, 남은 몫을 나머지 관절로 다시 계산 (최대 8번).

| A | 전체 | 할 수 있는 목표 | 한계에 걸린 프레임 (할 수 있는 목표) | 그중 성공 | 안 걸린 프레임 성공 | 30° 튐 | 시간 중앙 / 95% |

## 5. 비교 실행: C 풀이 방식 격자(본 결과) 대 SEW 고정(멘토 제안)

설정에서 C `select`만 바꿈. SEW 고정 = 사람 SEW 각으로 팔꿈치 고정 → 1·2·3번 관절을 기하로 → EAIK 해석해 → 직전 프레임과 가장 가까운 해. 한계 밖이면 사람 각에서 1°씩 벌림.

| C | 전체 | 할 수 있는 목표 | 팔 회전각 차이 중앙 / 95% | 관절이 한계에 붙은 프레임 | 2번 관절 | 30° 튐 | 시간 중앙 / 95% |
|---|---|---|---|---|---|---|---|
| **격자** (본 결과) | 72.1% | 100% | 24.9° / 54.5° | 48.7% | 41.7% | 326 | 42 / 49 ms |
| SEW 고정 | 72.1% | 100% | 25.0° / 55.0° | **9.3%** | 6.1% | 331 | 43 / **260** ms |

- SEW로 직접 푼 프레임 71.5%, 그중 사람 SEW 각 그대로 풀린 것은 3,449프레임뿐. 보통 25°(95%: 55°) 벗어나야 관절 한계 안 해가 있음 (사람은 팔꿈치를 내리지만 iiwa 2번 관절 ±120°).
- 두 방식 모두 "한계 안에서 사람 SEW와 가장 가까운 자세"로 가서 결과가 같음. 격자는 0.1°까지 다듬어 한계에 딱 붙은 해를, SEW 고정은 1°씩 벌리다 처음 들어온 해(한계에서 최대 1° 안쪽)를 골라 한계에 붙는 비율이 다름. 이 차이는 원리보다 탐색 간격에서 옴.
- 한계에 붙은 관절은 학습 데이터(7번, PR #51 "C 2번 관절 38% 한계")와 실제 로봇(넘치면 정지)에 불리. 미리 정한 기준(① 결과 같음 → ② 한계에 덜 붙는 쪽)으로는 SEW 고정.

## 8. 비교 실행: C 사람 팔꿈치 없이 (continuity)

지적: v1.3은 C만 사람 SEW 각을 입력으로 받아 A·B(손목만)와 공평한 비교가 아님. 남는 1자유도는 세 알고리즘 모두 어떤 기준으로든 정함 (A·B: 직전 해에서 출발·감쇠로 암묵적, C: 명시적) → C도 사람 팔꿈치 없이 돌려 본다.

설정 v1.3에서 C `select`만 `continuity`로 바꿈 (`~/out/hyojeong/retarget/cfg/v1_3_Ccont.json`). continuity = 3번 관절 1° 격자로 해를 전부 구하고 직전 프레임 자세와 가장 가까운 해 → 0.1°로 다듬기. 서버 `~/out/hyojeong/retarget/v1_3_Ccont`, 노드 DIS02 (2026-11-14 실행).

- 같은 입력 비교: A · B · **C 연속**
- 사람 SEW 입력 효과: **C 연속** 대 C SEW (공식) · C 격자

`compare_runs.py` (분모 = `v1_2` C 기준 목표 35,568 / 할 수 있는 목표 25,569프레임, 224개). 판정 손목 0.5 cm · 1° · 한계 안.

- **성공률은 사람 SEW 입력과 무관.** C 연속·격자·SEW 모두 72.1% / 100%. C는 할 수 있는 목표에서 늘 정확한 해를 찾고, SEW는 그 해들 중 하나를 고르기만 함 → C가 A보다 성공률이 높은 건 SEW 입력 덕이 아님. 이 지표는 v1.3 그대로 A·B·C를 비교해도 공평.
- **팔 회전각 차이 25°는 전부 사람 SEW 입력 덕.** C 연속 135.1°는 B 135.5°와 같음. 이 지표는 같은 입력끼리만 비교 (A·B·C 연속 / 또는 모두 사람 팔꿈치를 쓴 v1.1).

- C 연속은 사람 SEW 각에서 벌려 찾는 탐색이 없어 시간 95%도 40 ms (SEW 260 ms).

## 9. 비교 실행: C 해 선택 smooth (해 바뀜 튐 대책)

문제: C SEW(v1.3 공식)는 저크 RMS 평균 7,140으로 A 3,843 · B 2,868보다 큼 (5-2 `metrics_v1_3`, 최대 44,150 T1_E067). 프레임마다 "직전 자세와 가장 가까운 해"를 고르는 탐욕 방식이라, 쓰던 해가 관절 한계·도달 범위 밖으로 사라지는 순간 다른 갈래로 한 번에 넘어감 → 관절 튐. 사람 팔 자세(팔 회전각)는 유지하면서 튐만 줄이는 해 선택 규칙이 필요.

`select=smooth` (`eaik_ik.py`, 브랜치 `retarget/c-smooth-select`): 에피소드 전체를 보고 해 경로를 고름.
1. 프레임마다 후보 = 3번 관절 5° 격자 × EAIK 해 (한계 안, 정확한 해 우선)
2. 후보 점수 = `w_swivel` × (사람과 팔 회전각 차이)² + `w_limit` × (관절 한계 10° 안으로 들어간 정도)²
3. 이웃 프레임 비용 = Σ (관절 속도 / 속도 한계)² + `w_over` × Σ (속도 한계 넘은 만큼)²
4. Viterbi(DP)로 전체 비용이 가장 작은 경로 → 갈래를 바꿔야 하면 앞으로 올 프레임까지 보고 두 갈래가 가장 가까운 프레임에서 미리 바꿈
5. 고른 경로의 3번 관절 값을 가우시안 스무딩(σ 2프레임) → 다시 풀어 같은 갈래 해로 (손목은 그대로 정확)
