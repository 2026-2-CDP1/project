## 최종 결정과 이유

**MuJoCo로 정한다.** (a)에서 막혔고, 풀려면 OS 업그레이드나 드라이버 업그레이드(관리자 권한)가 필요하다.

연구에 미치는 영향은 없다고 본다.
- MuJoCo 재생 트랙의 지표는 관절 각도로 위치를 계산하는 기구학 계산이다. 물리엔진 차이(마찰·질량 등)가 결과에 들어가지 않는다.
- 5-2번 지표(관절 한계 위반·포화율, 자기 충돌률, 최대 침투 깊이, IK 실패율, 저크 RMS, 파지점 거리)는 모두 MuJoCo로 계산할 수 있다. 자기 충돌과 침투 깊이는 MuJoCo 접촉(`mj_forward` 후 `data.contact`, `dist`)으로 읽는다.
- 알고리즘 B(mink)가 원래 MuJoCo 모델 위에서 동작하므로, 시뮬레이터와 IK 도구가 같은 `robot.xml`을 쓴다.
- 선택 항목 (d) 파지 유지 판정은 하지 않는다.

## 나중에 바꿀 여지

- 재생 함수를 `replay(q_traj, gripper)` 형태로 고정해 두면, 서버 드라이버가 535 이상으로 올라갈 경우 Isaac Sim 4.5 컨테이너로 내부만 바꿀 수 있다.
- 서버 관리자에게 GPU 노드 드라이버 업그레이드가 가능한지 문의하는 것은 선택 사항이다(`PROJECT_CONTEXT.md` 9절 보류 항목).
- GPU 공유: Isaac Sim을 다시 검토하더라도 OpenVLA LoRA 학습(약 27GB)과 Isaac Sim(최소 16GB)을 48GB 한 장에서 동시에 돌릴 여유는 작다. 7번 담당과 시간대를 나눈다.
