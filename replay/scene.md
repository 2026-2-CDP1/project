# 환경 장면 (테이블·장애물)

> 담당: 신서연 (5-1 궤적 재생)
> 상태: **초안 (2026-11-05)** — 테이블 크기와 4번 좌표 변환이 들어오면 확정. 확정 뒤에는 결과를 보기 전과 같은 장면만 쓴다.
> 쓰는 곳: 지표 정의서 2.9 환경 충돌률·환경 최대 침투 깊이 (참고 지표, 순위에 안 씀)

로봇 팔이 테이블이나 장애물을 파고드는지 보려고, 에피소드마다 재생 장면에 상자를 넣는다. 코드는 `replay/scene.py`, 설정은 `replay/scene_config.json`.

---

## 1. 무엇을 넣나

| 상자 | 출처 | 좌표 |
|---|---|---|
| 장애물 (방해물·아크릴 판 등) | 3번 `obstacles.json` (`episodes/tools/obstacles.py`) — 에피소드마다 `{center, size, yaw_deg}` | 테이블 좌표계 |
| 테이블 | `scene_config.json`의 테이블 윗면 사각형 `x`, `y` 범위와 두께. 윗면이 z = 0 | 테이블 좌표계 |

- 장애물이 없는 에피소드는 테이블만 넣는다 (정의서 2.9).
- 테이블 크기가 설정에 없으면 테이블 없이 장애물만 넣고 경고한다. **지금은 비어 있음 (측정 필요, 3절).**

## 2. 로봇 좌표로 옮기는 법

4번 가이드의 좌표 변환은 단순한 좌표계 바꾸기가 아니라 **사람 어깨를 기준으로 축척을 곱하는 변환**이다.

```
p_robot = p_robot_shoulder + s · R_tb · (p − p̄_human_shoulder)      (4번 to_robot_point)
```

로봇 목표 궤적이 이 변환으로 만들어지므로, 장애물도 **같은 변환**으로 옮겨야 로봇 손과 장애물의 상대 위치가 사람 영상과 같아진다. 그래서:

- 상자 꼭짓점 8개를 `to_robot_point`로 하나씩 옮기고, 옮긴 꼭짓점으로 상자를 다시 세운다 (`scene.map_box`).
- 이 변환은 평행 이동 + 축척 + 회전이라 상자는 상자로 남고 **크기는 s배**가 된다. s나 R_tb를 따로 받을 필요가 없다.
- 변환이 상자 모양을 깨면(축마다 축척이 다르거나 기울어짐) 오류를 낸다. 그런 변환이면 장면을 그대로 옮길 수 없으니 4번과 다시 정해야 한다.
- s와 사람 어깨 평균이 에피소드마다 달라서 **장면도 에피소드마다** 만든다.

## 3. 정할 것 (결과 보기 전에)

| 항목 | 지금 | 필요한 것 |
|---|---|---|
| 테이블 윗면 크기·위치 | 비어 있음 | 테이블 좌표계(체커보드 원점, x = front에서 오른쪽, y = 작업자 쪽)에서 테이블 윗면 네 변의 위치 (m). 태스크·세션마다 체커보드 위치가 달랐으면 태스크별로 |
| 테이블 두께 | 0.03 m (임시) | 윗면만 보면 되므로 두께는 결과에 거의 영향 없음 |
| 테이블과 검사에서 뺄 로봇 몸체 | `link1` (제안) | 아래 4절 |
| `to_robot_point` 형태 | 4번 코드 없음 | 에피소드마다 s·사람 어깨가 달라서 `to_robot_point(p)`가 어느 에피소드 값을 쓰는지 정해야 함 (예: `to_robot_point(p, ep_dir)`) — 질문 T9 |

## 4. 테이블과 로봇 아래쪽 몸체

- `base`와 테이블은 **둘 다 월드에 고정된 몸체**라 MuJoCo가 원래 서로 충돌 검사를 하지 않는다 (합성 검증으로 확인). 따로 뺄 필요 없음.
- `link1`(어깨 아래 기둥)은 관절 1로 수직축 둘레만 돈다. 2절 변환에서는 로봇 베이스와 옮긴 테이블 면의 높이 관계가 축척·사람 어깨 위치로 정해질 뿐 실제 설치 높이가 아니다. 그래서 테이블 면이 `link1` 높이에 오면 **어느 알고리즘이든 모든 프레임에서** 닿는다. 이건 알고리즘 차이가 아니라 장면을 옮기며 생긴 것이라 `link1`–테이블은 검사에서 빼자고 제안한다.
- 장애물은 모든 로봇 몸체와 검사한다.
- 테이블이 들어오면 실제 에피소드 몇 개를 `--show`로 열어 home 자세에서 어느 몸체가 테이블에 닿는지 보고 이 목록을 확정한다.

## 5. 검증 (`python replay/scene.py --check`)

2026-11-05 노트북 (mujoco 3.14.0): **6/6 통과** — 결과 `scene_check_result.md`

| 검사 | 내용 |
|---|---|
| 항등 변환 | `obstacles.json` 상자(yaw 30°)가 위치·크기·방향 그대로 |
| 축척 0.8 + 90° 회전 | 4번 변환 형태로 옮기면 크기 0.8배, 중심·방향이 변환대로 |
| 축마다 다른 축척 거부 | 상자 모양이 깨지는 변환은 오류 |
| 환경 접촉 검출 | home TCP 자리 상자에 닿고, 팔을 돌리면 안 닿음. 로봇 몸체 목록은 그대로 |
| base는 테이블과 검사 안 함 | 베이스를 관통하는 판에도 `base` 접촉 없음 |
| 테이블 제외 쌍 | `(link1, env_table)`을 빼면 그 접촉이 사라짐 |

- 기존 `replay.py --check`(무작위 2000 자세)는 장면을 넣기 전과 결과가 같다 (자기 침투 base–link6 8, base–link7 4, base–link5 3).

## 6. 해석할 때 주의

- 알고리즘들은 장애물 위치를 모르고 푼다. 이 지표는 "팔꿈치 자세가 우연히 피해 갔는가"를 재므로 **참고용**이다 (정의서 2.9).
- 장애물 위치는 사람이 영상에서 바닥 끝점을 찍어 만든 것이고 높이는 잰 값이다 (3번 `obstacles.py`). 몇 cm 오차가 있을 수 있다.
- 상자 크기도 s배로 옮겨지므로, 로봇 장면의 장애물은 실제 크기가 아니라 "로봇 팔 길이에 맞춘" 크기다.
